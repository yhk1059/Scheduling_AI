# UI 디자인 가이드

제품 이름은 **말로**다("말로 짜는 근무표"). 시안: [말로 디자인 시안](https://claude.ai/artifact/CCGFVEsAp3ffAkCXuKyD66) (디자인 시스템 · 랜딩 · 샘플 데모 · 로그인 · 매장 홈 · 근무표 작성 ③ · 확정 근무표 · 직원 가능 시간 입력). 결정 기록은 `docs/DESIGN_BRIEF.md`에 있다. 라이트 테마. 데스크톱(1280px 이상) 전용이다.
시안에 없는 화면(매장 준비, 매장 설정, 근무표 작성 ①②)은 아래 색상·컴포넌트 규칙을 그대로 따른다.

## 디자인 원칙
1. **근무표가 주인공이다.** 어느 화면이든 가장 크고 선명한 것은 근무표이거나 그것을 만드는 입력이다. 랜딩 첫 화면은 근무표로 시작한다. 규칙 카드 목록은 근무표 다음이다.
2. **말이 인터페이스다.** 자연어 입력 바는 화면의 중심 요소다. 여느 입력창보다 크고(높이 48px), 예시 문장이 보이고, 결과 카드는 "내 말이 이렇게 읽혔다"는 답장처럼 원문 인용과 해석을 시각적으로 잇는다.
3. **위계가 먼저, 밀도는 그다음.** 화면의 내용을 "지금 할 일 / 확인할 것 / 접어둔 것" 세 단계로 나누고, 타이포 스케일과 여백으로 구분한다. 표 안은 촘촘하게 둔다.
4. **색은 뜻이 있을 때만, 대신 과감하게.** 근무 코드(A/M/C/O)와 상태(성공·오류·주의·변경)에만 색을 쓴다. 강조색은 하나지만 브랜드 표면(워드마크, Primary, 현재 단계, 칠한 가능 시간, 선택된 칸, 입력 바 영역)에는 면으로 쓴다.
5. **장식 히어로는 금지, 제품 히어로는 허용.** 일러스트, 배경 도형, 스톡 이미지를 두지 않는다. 실제 제품 화면이 움직이는 장면이 장식 역할을 한다. 그림자는 떠 있는 것(메뉴, 대화상자, 드래그 중인 요소)에만 쓴다.
6. **결정은 사람이 한다.** LLM이 해석한 결과는 항상 카드로 제안되고, [적용]이나 [수락]을 누르기 전에는 근무표에 반영되지 않는다.
7. **되돌릴 수 있는 동작은 묻지 않는다.** 바로 하고 되돌리는 버튼을 둔다. 되돌릴 수 없는 동작만 확인을 받는다.
8. **움직임은 상태 변화를 설명할 때만.** 카드가 생길 때, 칸이 바뀔 때, 단계가 넘어갈 때 120~240ms. 장식 애니메이션과 끝없는 루프는 두지 않는다. 랜딩 히어로 시퀀스만 예외이고 한 번 재생 후 [다시 보기]다. `prefers-reduced-motion`이면 즉시 전환한다.

## 화면 구조
```
/a/{공용 토큰}    직원 가능 시간 입력. 로그인 없음
/app
├── 로그인 화면   로그인하지 않았을 때
├── 매장 준비     매장이 없을 때 한 번
├── 매장 홈       기본 화면 (탭 이름은 [근무표])
├── 매장 설정     탭: [명단·필요 인원] [근무 형태] [매장 조건]
├── 근무표 작성   작성 중인 근무표. 스테퍼 ① 가능 시간 → ② 매장 조건 → ③ 근무표, 끝 버튼 [확정]
└── 확정 근무표   확정한 근무표(운영 중·시작 전·지난). 스테퍼 없음
```
- **이동**
  - 상단 바 아래에 [근무표] [매장 설정] 탭을 둔다. 탭은 높이 44, `text-sm font-medium text-[#3D3D38]`, 현재 탭은 `font-semibold text-[#1B1B18] border-b-2 border-[#155E75]`과 `aria-current="page"`로 표시한다.
  - 근무표 작성·확정 근무표 화면에서는 제목 위의 "← 근무표 목록" Text 링크로 돌아간다.
  - 매장 준비 중에는 탭 줄을 숨긴다.
  - 근무표를 열면 상태로 화면이 정해진다: 작성 중 → 근무표 작성(근무표를 만들었으면 ③, 아니면 ①), 확정 → 확정 근무표.
- **로그인 화면**: 상단 바에는 워드마크와 [데모 영상 보기] Text만 둔다(탭 줄 없음). 본문은 두 열이다. 왼쪽은 워드마크(마크 36 + 글자 32) + "말로 짜는 근무표"(36px) + 설명 한 줄 + 번호 3줄(명단과 링크 → 말로 조건 → 근무표 확정). 오른쪽은 `max-w-[440px] rounded-xl` 카드에 "로그인" 제목, "Google 계정으로만 로그인할 수 있어요" 보조, [Google로 로그인] Primary(높이 48, 가로 꽉 참), "또는" 구분선, [데모 영상 보기] Secondary(영상 대화상자), 저장·삭제 안내 한 줄과 [개인정보처리방침] 링크. 로그인한 뒤 매장이 없으면 매장 준비를 연다.
- **근무표 이름**: 화면에서는 기간을 "근무표"로 부르고 날짜로 이름을 붙인다. 달력 월이면 "11월 근무표", 주 단위면 "11/2~11/8 근무표". 제목과 카드에는 이 이름을 쓰고, 정확한 날짜 범위(mono)는 그 옆에 보조로 둔다.

### 매장 홈
홈은 "지금 할 일"을 먼저 보여 준다. 위에서부터 다음 순서로 놓는다.
1. **제목 줄**: 매장 이름(페이지 제목) + 오른쪽에 매장 요약 한 줄 "직원 12명 · 매장 조건 6개 · 1주 단위" + [매장 설정] Text. 매장 조건 수에는 필요 인원을 넣지 않는다(모든 화면에서 같게 센다).
2. **운영 중 근무표 카드**(오늘이 속한 확정 근무표가 있을 때만): "10월 근무표", `운영 중` 배지, "마지막 확정 10/28 14:32", [변경 입력] Secondary. 누르면 확정 근무표 화면을 열고 변경 입력 바에 포커스를 둔다
3. **지금 할 일 카드**(다음 근무표): 홈에서 가장 큰 면이다. 강조 바탕 패널(`bg-[#F0F6F8] border-[#CFE4EA] rounded-xl px-8 py-7`) 안에 "지금 할 일" 아이브로우, 근무표 이름과 상태 문장(22px), 진행 단계 한 줄(① 가능 시간 → ② 매장 조건 → ③ 근무표 → 확정, 끝난 단계는 체크), 버튼 하나(높이 44). 홈의 유일한 Primary다. 오른쪽 320px에는 작성 중일 때만 직원 링크 카드(링크 mono, [링크 복사], "{제출}/{전체}명 제출" 진행 막대, 미제출 이름, [새로고침])를 붙인다.
   | 상태 | 문장 | 버튼 |
   |---|---|---|
   | 없음 | "12월 근무표를 만들 차례예요" | [12월 근무표 만들기] |
   | 작성 중, 생성 전 | "{근무표 이름} · 직원 링크를 공유하고 조건을 확인하세요" + 보조 줄 "아직 근무표를 만들지 않았어요. {n}명 중 {m}명이 가능 시간을 제출했어요." | [이어서 하기] |
   | 작성 중, 생성 후 | "근무표를 만들었어요. 확인하고 확정하세요" | [근무표 확인하기] |
   | 확정 | "확정했어요 · 10/28 14:32" | [열기] (Secondary, 이때는 다음 근무표 만들기가 Primary) |
4. **지난 근무표 표**: 확정한 지난 근무표만 둔다. 열은 근무표 이름, 기간(mono), 확정(시각 mono, 다시 확정한 횟수), 마감 횟수 차이(가장 적음 ~ 가장 많음, mono), [열기 →] Text. 행을 누르면 그 근무표의 확정 근무표 화면(보기 전용)으로 간다. 비어 있으면 표 대신 "확정한 근무표가 여기에 쌓여요" 한 줄만 둔다. 지금 할 일 카드와 같은 근무표를 다시 보여 주지 않는다.

### 매장 준비
- **제목**: "매장 준비"(페이지 제목). 스테퍼 없음
- 매장 설정 "기본" 영역(매장 이름, 근무표 주기)과 명단 표. 오른쪽 아래 [첫 근무표 시작하기] Primary. 직원이 없으면 비활성이고 "명단에 직원을 1명 이상 넣으면 시작할 수 있어요" 한 줄
- 입력은 매장 설정과 같은 컴포넌트를 쓴다. 바꾼 내용은 바로 저장된다

### 근무표 작성
- **제목**: 근무표 이름("11월 근무표", 페이지 제목) + 날짜 범위(mono, 보조) + `작성 중` 배지
- **스테퍼**: 제목 아래에 둔다. 이미 지난 단계는 언제든 눌러 돌아갈 수 있다. 단계마다 오른쪽 아래 Primary 하나, 왼쪽 [이전] Secondary(①에는 없음)
  - **① 가능 시간**
    - 맨 위에 준비 요약 카드 한 줄: 날짜 범위(mono) · 공휴일 n일(없으면 "공휴일 없음") · 직원 n명 · 지난 근무("지난 근무표에서 이어져요" / "지난 근무 없음") + [바꾸기] Text(`aria-expanded`)
    - 펼치면 날짜, 공휴일 체크, 명단 확인, 지난 근무 마지막 며칠을 둔다.
      - 명단 확인: "지난 근무표 이후 2명 추가 · 1명 제외"처럼 바뀐 사람 요약. 바뀐 사람이 없으면 "지난 근무표와 명단이 같아요". + [매장 설정] Text
      - 지난 근무 마지막 며칠: 지난 확정 근무표가 있으면 읽기 전용 표. 없으면(첫 근무표) 접힌 "지난 근무 입력하기 (선택)" Text 버튼만 두고, 펼치면 붙여넣기 입력과 예시 한 줄을 보여 준다.
      - 날짜: 첫 근무표는 시작일 date 입력(기본값 오늘 이후 첫 월요일 또는 1일, 달력 월 단위는 1~28일만)과 끝 날짜(읽기 전용, mono). 다음 근무표는 날짜를 읽기 전용으로 두고 [시작일 미루기] Text를 둔다. 미루면 "지난 근무표와 이어지지 않아서 지난 근무를 직접 입력해요" 한 줄을 보인다. 시작일이 바뀌면 링크를 새로 만든다.
    - 그 아래 직원 링크 카드: 공용 링크(mono, 말줄임), [링크 복사] Secondary. 복사하면 그 자리의 글자가 "복사했어요"로 바뀐다. 위 한 줄 "단체 대화방에 이 링크 하나만 올려 주세요. 직원이 자기 이름을 골라 가능 시간을 입력해요". 아래 줄에 "{전체}명 중 {제출}명 제출", "미제출: 이름, 이름", [새로고침] Text
    - 그 아래 "직원별 가능 시간"(읽기 전용, 고칠 수 없다): 제목 옆에 색 견본과 "칠한 곳이 일할 수 있는 시간이에요" 한 줄. 맨 위에 날짜별 가능 인원 표(근무조 × 날짜, 근무조 시각을 완전히 덮는 직원 수. 스크롤해도 위에 붙는다). 그 아래 직원별 미니 캘린더를 명단 순서로 한 줄에 3개씩 둔다(06:00~24:00, 3시간마다 시각, 칠한 구간은 `bg-[#155E75]` 덩어리 하나이고 마우스를 올리면 시각이 보인다). 미제출 직원은 빈 캘린더에 "미제출" 배지. 2주 이상이면 [이전 주] [다음 주] Text로 표와 캘린더를 함께 넘긴다. [새로고침]으로 함께 갱신된다
    - 오른쪽 아래 [다음] Primary. 미제출 여부로 막지 않고 경고도 두지 않는다
  - **② 매장 조건**: 근무조·필요 인원 요약표 + 자연어 입력 바(근무 형태·필요 인원·규칙을 한 곳에서 말로) + 예시 Text 버튼 + 접힌 "숫자로 입력하기"(아래 "필요 인원 폼") + 규칙 카드, [모두 적용]. 오른쪽 아래 [다음] Primary(항상 누를 수 있다)
    - 맨 위 요약표: 근무조마다 이름, 시각, 평일·주말 필요 인원을 한 줄씩 보여 준다. 요약표에 든 필요 인원 규칙은 카드로 다시 보여 주지 않는다. [바꾸기] Text(`aria-expanded`)로 펼치면 매장 설정 [근무 형태] 탭과 같은 근무 코드 표다
    - 입력 바: 제목 아래 설명 한 줄 "근무 형태, 필요 인원, 지켜야 할 규칙 모두 한 곳에서요.". 예시 Text 버튼 3개("평일 오픈 2명, 주말은 3명", "12시부터 15시까지는 최소 3명", "마감 다음 날 오픈은 안 되게"). 생긴 카드는 [적용]해야 반영된다
    - 필요 인원 규칙이 하나도 없으면 Primary 옆에 "필요 인원 없이 만들면 인원을 맞추지 않아요" 한 줄. 적용 대기 카드가 남아 있으면 "적용하지 않은 규칙 2개는 빠져요" 한 줄
  - **③ 근무표**: 위에서부터 예외 입력 패널(강조 바탕 패널 안에 "이번 근무표에만 적용할 예외가 있나요?" 제목, 설명 한 줄, 자연어 입력 바. 오른쪽 5/12에 요청 카드) → 요약 지표(왼쪽) + "칸을 누르면 바꿀 수 있어요. 🔒 고정한 칸은 다시 만들 때 그대로 둬요" 한 줄(오른쪽) → 근무표(해 없음이면 그 자리에 해 없음 패널) → 버튼 줄 → 개인별 통계 표. 지난 근무표가 바뀌었으면 맨 위에 지난 근무 변경 배너 + [다시 만들기]. 접지 않는다.
- **③ 근무표의 버튼**: 지금 할 일 하나만 Primary다.
  | 상태 | Primary | 그 밖 |
  |---|---|---|
  | 만들기 전 | [근무표 만들기] | 설명 한 줄 "가능 시간과 매장 조건으로 근무표를 만들어요"만 둔다. 칸 고정 안내는 근무표가 생긴 뒤에 보여 준다 |
  | 만든 뒤 | [확정] (높이 44) | 왼쪽 [이전] Secondary. 오른쪽 [CSV 받기] Text, [다시 만들기] Secondary, [확정] 순서 |
- 가능 시간을 다시 불러와 달라졌으면 "가능 시간이 바뀌었어요. 다시 만들어 주세요" 주의 배너 + [다시 만들기]. 다시 만들 때까지 [확정]은 비활성이다
- [확정]을 누르면 확정 근무표 화면으로 옮겨 가고 직원 링크가 잠긴다.
- 해 없음의 "함께 지킬 수 없는 규칙"에 가능 시간도 "이영희 가능 시간"으로 나오지만, [이번 근무표에서만 끄기]와 완화 제안을 두지 않는다.

### 직원 가능 시간 입력
- 앱의 상단 바와 탭을 쓰지 않는다.
- 맨 위 줄은 작은 워드마크(마크 18 + "말로" 13px) + "· 가능 시간 입력" 보조 글자다. 그 아래 페이지 제목(28px)에 매장 이름을 크게 쓴다. 직원은 어느 매장의 어느 주인지 먼저 봐야 한다.
- **이름 고르기**: 제목 "{매장 이름} · 가능 시간 입력", 날짜 범위(mono), "내 이름을 골라 주세요"와 이름 칩(높이 44, `rounded-full border-[#C9C9C1]`, 제출한 이름에 "제출함" 배지). 제출한 이름을 고르면 "{이름}님은 이미 제출했어요. 본인이 맞으면 이어서 고칠 수 있어요" 배너와 [이어서 고치기] [취소] Text. 좁은 화면에는 "PC에서 입력해 주세요. 휴대폰에서는 드래그할 수 없어요" 한 줄
- **입력**: 제목 "{매장 이름} · {직원 이름}님의 가능 시간"(28px), 아래 한 줄 "{날짜 범위} 근무표예요. 일할 수 있는 시간을 드래그해서 칠해 주세요. 칠한 칸에서 시작하면 지워져요", 오른쪽 [이름 다시 고르기] Text
- **캘린더**: 두 열 배치다. 왼쪽은 캘린더(`flex-1`), 오른쪽 260px은 "이번 주 칠한 시간" 카드(요일마다 시작~끝 mono, 합계 시간), "매장 근무조" 카드(코드·이름·시각, "근무조 시간을 다 덮어야 그 근무에 들어갈 수 있어요". 휴무·꺼진 근무조·복합 코드는 빼고, 근무조가 없으면 카드를 그리지 않는다), 안내 두 줄(다시 고칠 수 있음, 확정되면 잠김).
  - 캘린더 열은 날짜(요일 + 일, 토 `text-[#155E75]` 일 `text-[#B42318]`), 행은 06:00~24:00 30분 칸(왼쪽에 1시간마다 시각, mono, 정시 줄은 `border-[#E2E2DC]` 반시 줄은 더 옅게). 한 화면에 최대 7일이고, 2주 이상이면 [이전 주] [다음 주] Text로 넘긴다. 세로 스크롤 없이 들어가도록 칸 높이를 화면에 맞춘다(최소 14px, 기본 16px). 주말 열 바탕은 `bg-[#F6F4EE]`
  - 드래그: 빈 칸에서 시작하면 칠하고, 칠한 칸에서 시작하면 지운다. 같은 날 열 안에서만 칠한다. 드래그 중인 선택 영역에는 그림자를 쓴다
  - 칠한 칸은 `bg-[#155E75]`. 칸은 `button`이고 `aria-pressed`, `aria-label="{M}월 {D}일 {시작}~{끝}"`을 가져 키보드로 하나씩 토글할 수 있다.
- 아래 고정 줄(`sticky bottom-0 bg-white border-t`, 높이 72)에 왼쪽 개인정보처리방침 링크, 오른쪽 "{n}일 · {시간}시간 칠했어요" + [제출] Primary(높이 48). 제출 뒤 "제출했어요. 이 링크로 다시 고칠 수 있어요" 한 줄
- 잠긴 뒤(확정): 칠한 내용을 보기 전용으로 두고 "이미 확정된 근무표예요" 한 줄. 토큰이 틀리면 "링크를 확인해 주세요"만 보인다

### 확정 근무표
- **제목**: 근무표 이름(페이지 제목) + 날짜 범위(mono, 보조) + `운영 중` 또는 `확정` 배지 + 오른쪽에 "마지막 확정 10/28 14:32"
- 스테퍼를 두지 않는다. 확정한 뒤에는 요청 단계로 돌아가지 않고, 늦게 온 요청·병가·휴가는 모두 변경 입력으로 넣는다(시작 전에 확정한 근무표도 같다).
- 제목 오른쪽에 "마지막 확정 10/28 14:32 · 직원 링크는 잠겼어요".
- 위에서부터: 배너(지난 근무 변경 + [다시 만들기]: 최소 변경으로 다시 만들고 [다시 확정]을 기다린다) → 변경 입력 패널(강조 바탕 패널. "변경 입력" 제목, 설명 한 줄 "확정한 뒤 생긴 병가·휴가를 적으면, 확정 근무표에서 최소한으로 바꿔 다시 만들어요. 이미 지난 날은 건드리지 않아요", 자연어 입력 바. 오른쪽 5/12에 변경 카드) → 바뀐 칸 요약 배너("2명, 5칸 변경 · 주황 테두리 칸이 바뀐 곳이에요. 아직 다시 확정하지 않았어요", 왼쪽) + 요약 지표(오른쪽) → 근무표(표 위에 "오늘은 11/4 수예요. 지난 날짜는 🔒 자동으로 고정돼요" 한 줄) → 버튼 줄 → 확정 기록(확정 시각 mono, 바뀐 칸 수. 비교·복원은 없다) → 통계 표
- 홈 운영 중 카드의 [변경 입력]으로 들어오면 변경 입력 바에 포커스를 둔다. 그 밖의 경로(작성의 [확정], 홈 [열기])에서는 제목에 둔다.
- 변경 카드를 [적용]하면 바로 최소 변경으로 다시 만든다.
- **버튼**: 지금 할 일 하나만 Primary다.
  | 상태 | Primary | 그 밖 |
  |---|---|---|
  | 변경 없음 | 없음 | [CSV 받기] Secondary |
  | 변경 있음 | [다시 확정] (높이 44) | 왼쪽 [변경 취소] Text(마지막 확정본의 배정과 요청으로 되돌림, 확인 없이 바로). 오른쪽 [CSV 받기] Text, [다시 확정] |
- **끝난 근무표**(오늘이 근무표 뒤): 보기 전용. 변경 입력 카드와 칸 편집이 없고 [CSV 받기] Secondary만 둔다.

### 매장 설정
- 탭은 [명단·필요 인원] [근무 형태] [매장 조건] 순서다.
- 탭 [명단·필요 인원]: 맨 위에 "기본" 영역(매장 이름, 근무표 주기 select: 한 달(1일~말일) / 1주 / 2주 / 4주)을 두고, 그 아래 명단 표와 필요 인원 폼을 둔다.
- 명단 표 위에 "바꾼 내용은 바로 저장돼요" 한 줄을 둔다(저장 버튼이 없다는 것을 알린다).
- 명단 표 맨 아래에 입력 줄(이름, 태그, [추가] Text)을 둔다. 명단이 비어 있어도 이 줄은 보인다.
  - 이름 칸에서 Enter를 누르거나 [추가]를 누르면 한 명이 더해지고, 입력 줄이 비워진 채 이름 칸으로 포커스가 돌아간다.
  - 이름이 비었거나 같은 이름이 있으면 더하지 않고 그 칸에 오류를 보인다.
  - 태그 칸은 선택 입력인 칩 입력이다. Enter나 쉼표로 칩을 만들고, 매장에 있는 태그를 자동 완성한다. 사람당 5개까지. 칸 아래 보조 한 줄 "태그에는 이름을 쓰지 마세요"
  - 활성 직원이 40명이면 입력 줄 대신 "직원은 최대 40명까지 넣을 수 있어요."를 둔다.
- 필요 인원 폼: 활성 근무조(복합 코드 제외, 기본 A/M/C) × 평일/주말·공휴일. 칸마다 최소·최대 숫자 두 개 + "명"("3 ~ 4 명"). 최대를 비우면 "이상", 둘이 같으면 정확히 그 인원이다. 값은 필요 인원 기본 규칙 카드와 같은 것을 고친다.
  - 제목 아래 설명 한 줄: "하루에 그 근무조에 들어갈 직원 수예요. 최대를 비우면 그 이상이면 돼요."
  - 근무조 합계로 "쉴 사람이 없어요" 같은 오류를 띄우지 않는다. 복합 코드와 다른 규칙 때문에 합계로는 판정할 수 없다. 만들 수 없으면 근무표를 만들 때 해 없음 패널이 이유를 알려 준다.
  - 숫자가 아니면 그 칸을 오류로 두고 "인원은 숫자로 적어 주세요."를, 최소가 최대보다 크면 "최소가 최대보다 커요."를 보인다.
  - 말로 만든 필요 인원 규칙이 폼의 모양(근무조 × 평일/주말·공휴일)에 맞지 않으면(예: 토요일만) 폼에 나오지 않고 매장 조건 카드로만 보인다.
- 탭 [근무 형태]: 근무 코드 표(코드 · 이름 · 시작 시각 · 끝 시각 · 실근무 시간 · 세는 근무조). 맨 아래 입력 줄로 추가한다(명단 표와 같은 방식). 세는 근무조를 둘 고르면 복합 코드(더블)다. `O`(휴무)는 고칠 수 없어 표에 보여 주지 않고, 새 코드로도 쓸 수 없다. 한 번이라도 쓰인 코드는 [지우기] 대신 [끄기]이고, 끈 코드는 새 근무표에 배정되지 않는다. 표 위 한 줄 "말로 '피크 근무 11시~14시 추가'라고 적어도 돼요"
- 탭 [매장 조건]: 근무표 작성 ②와 같은 입력 바 + 규칙 카드. 기본 규칙(필요 인원) 카드는 맨 위에 `기본` 배지로 두고, [삭제] 대신 [끄기]다.
- 근무표 주기를 바꾸면 "다음에 만드는 근무표부터 적용돼요. 최소 휴무 일수 같은 규칙 값을 다시 확인하세요"를 주의 배너로 보여 준다. 근무표가 아직 없으면 보이지 않는다.

## 컴포넌트
모서리는 크기에 따라 다르게 한다: 셀 `rounded-xs`(2px) · 배지 `rounded-sm`(4px) · 버튼·입력 `rounded-md`(6px) · 카드 `rounded-lg`(8px) · 큰 면(강조 바탕 패널, 로그인 카드, 히어로 패널) `rounded-xl`(12px).

### 워드마크
여는 따옴표 마크 + "말로" 글자. 마크는 "말"을, 글자는 제품을 뜻한다. 마크는 인라인 SVG(`rounded` 사각형 `#155E75` 안에 흰 따옴표 두 개, viewBox 24)이고 `aria-hidden`, 링크에는 `aria-label="말로 홈"`을 둔다.
| 자리 | 마크 | 글자 |
|---|---|---|
| 상단 바(앱·랜딩) | 22~24 | `text-[18px] font-bold tracking-[-0.02em]` |
| 로그인 왼쪽 열 | 36 | `text-[32px] font-bold` |
| 직원 가능 시간 입력 맨 위 줄 | 18 | `text-[13px] font-semibold` + "· 가능 시간 입력" 보조 |
| 강조 면 위 | 흰 사각형 + 청록 따옴표 | `text-white` |
| 글자만 쓰는 자리(탭 제목, 문장 안, 푸터) | 없음(푸터는 `#66665E` 마크) | "말로" |
- 자연어 입력 바 왼쪽에도 마크(18)를 둔다. 규칙·요청 카드의 원문 앞에는 따옴표 글리프만(`#155E75`, 16~20) 둔다.
- 마크를 늘리거나 색을 바꾸지 않는다. 다른 브랜드 색과 나란히 두지 않는다.

### 카드
```
rounded-lg bg-white border border-[#E2E2DC] px-[18px] py-4
```
- 적용 대기 카드: 테두리만 `border-[#C9C9C1]`로 한 단계 진하게
- 해 없음 패널: `border-[#E8B4AE]`
- 카드에 왼쪽 굵은 테두리 강조나 그림자를 넣지 않는다
- **강조 바탕 패널**: `rounded-xl bg-[#F0F6F8] border border-[#CFE4EA] px-6 py-5`. 자연어 입력 바를 담는 영역(근무표 작성 ②③, 확정 근무표 변경 입력, 매장 설정 [매장 조건])과 매장 홈 지금 할 일 카드, 랜딩 히어로 패널에만 쓴다. 한 화면에 하나다.

### 버튼
```
공통:      inline-flex items-center gap-2 h-10 px-4 rounded-md text-sm font-medium transition-colors duration-[120ms]
Primary:   bg-[#155E75] text-white border border-[#155E75] hover:bg-[#0E4A5C] active:bg-[#0B3F4E]
Secondary: bg-white text-[#1B1B18] border border-[#C9C9C1] hover:bg-[#EFEFEB]
Text:      px-2 text-[#3D3D38] hover:bg-[#EFEFEB] hover:text-[#1B1B18]
Danger:    px-2 text-[#B42318]  (삭제 등)
Disabled:  bg-[#EFEFEB] text-[#9A9A91] border border-[#E2E2DC] cursor-not-allowed
카드 안:   h-8 text-[13px]
화면의 Primary(근무표 만들기·확정·다시 확정·이어서 하기·제출): h-11 text-[15px] px-5
랜딩·로그인: h-12 text-[15px] px-[22px]
입력 바 안: h-9 px-3.5
예시 칩:   h-7 rounded-full border-[#C9C9C1] bg-white text-xs font-normal
```
한 영역에 Primary는 하나만 둔다.
- **배치**: Primary는 영역의 오른쪽 끝에 둔다. Danger는 Primary와 떨어뜨려 왼쪽에 두거나 메뉴 안에 넣는다. 바로 옆에 붙이지 않는다.
- **레이블**: 눌렀을 때 일어나는 일을 동사로 쓴다("근무표 만들기", "적용", "12월 근무표 만들기"). "확인", "OK"처럼 결과를 알 수 없는 레이블은 쓰지 않는다.

### 입력 필드
```
h-10 rounded-md bg-white border border-[#8A8A80] px-3 text-sm text-[#1B1B18] placeholder:text-[#707068]
focus:outline-2 focus:outline-[#155E75] focus:-outline-offset-1 focus:border-[#155E75]
```
- 레이블은 항상 `<label>`로 위에 둔다: `text-xs font-medium text-[#3D3D38]`
- **자연어 입력 바**(규칙·요청·변경 입력 공통): 화면의 중심 요소다. 강조 바탕 패널 안에 제목(`text-[15px] font-semibold`) + 설명 한 줄(`text-[13px] text-[#3D3D38]`) + 바 + 예시 칩 줄 순서로 둔다.
  ```
  바:      flex items-center h-12 bg-white border border-[#8A8A80] rounded-lg pl-4 pr-1.5 gap-2.5
  마크:    왼쪽에 워드마크 마크 18 (aria-hidden)
  입력:    flex-1 border-0 outline-0 text-[15px]   (label은 sr-only)
  버튼:    바 안 오른쪽 Primary h-9 px-3.5 ("규칙 만들기" / "요청 만들기")
  포커스:  border-[#155E75] outline-2 outline-[#155E75] -outline-offset-1
  예시 줄: "예시" 보조 글자 + 예시 칩 3개. 누르면 입력에 채운다
  ```
  placeholder는 "예: 마감 다음 날 오픈은 안 되게"처럼 실제 말투 예시. 확정 근무표의 변경 입력 바는 홈 [변경 입력]으로 들어오면 포커스 상태로 연다.

### 배지
```
inline-flex items-center h-[22px] px-2 rounded-sm text-xs font-semibold
반드시:    bg-[#1B1B18] text-white          (hard)
가능하면:  bg-white text-[#3D3D38] border border-[#C9C9C1]   (soft)
검증됨:    bg-[#E6F2EA] text-[#1E6B3F]
적용 대기: bg-[#FDF0DC] text-[#7A4506]
근무표 없음: bg-[#FBE9E7] text-[#9F1F14]   (해 없음)
작성 중:   가능하면과 같음
확정:      검증됨과 같음
운영 중:   bg-[#E3F0F3] text-[#155E75]
이번 근무표에서 꺼짐: 적용 대기와 같음
제외:      bg-[#EFEFEB] text-[#66665E]   (비활성 직원)
```

### 반드시/가능하면 토글
화면에는 `hard`/`soft`를 쓰지 않는다. 버튼 글자는 "반드시" / "가능하면"이다.
```
컨테이너: inline-flex rounded-md border border-[#C9C9C1] overflow-hidden
버튼:     h-7 px-3 text-xs font-medium bg-white text-[#66665E]
선택됨:   aria-pressed="true" → bg-[#1B1B18] text-white
```

### 규칙·요청 카드 — 답장처럼
내 말(원문)과 그 아래 "이렇게 읽었어요" 해석이 이어지는 답장 모양이다. 위에서부터:
1. 제목(`text-[15px] font-semibold`, 식 모양의 이름: 필요 인원·휴가·마감 고르게…, 맞는 이름이 없으면 조건 규칙·세는 규칙·순서 규칙·고르게 규칙) + 오른쪽 반드시/가능하면 토글(가능하면이면 옆에 중요도 select 높음·보통·낮음)
2. 원문: 왼쪽 따옴표 글리프(`#155E75`, 20) + 원문 `text-[15px]`. 따옴표 문자(“…”)는 쓰지 않는다
3. 해석: `ml-2 border-l-2 border-[#CFE4EA] pl-3.5` 안에 아이브로우 "이렇게 읽었어요"(mono 11, `#155E75`) + 해석 문장 `text-sm text-[#1B1B18]` + 예시 판정
4. 상태 배지(왼쪽) + 버튼(오른쪽. 적용됨이면 수정·삭제, 대기면 삭제·적용)
카드 안 간격은 `gap-3.5`, 패딩 `px-5 py-[18px]`. 랜딩·홈 같은 작은 자리에서는 제목 14, 원문 14, 패딩 `px-4 py-3.5`로 줄인다.
- **해석 결과는 사람이 읽는 문장**으로 쓴다. 내부 id(`e01`), 근무 코드만 있는 표기(`C 뒤 A 금지`, `· O`)를 그대로 보여 주지 않는다. 날짜와 숫자만 mono로 둔다.
  - 예: "이영희 · 11/15~11/17 · 휴무", "마감 다음 날 오픈 금지", "박민수 · 주말·공휴일 · 마감 피하기"
  - 문장 틀은 "[사람] [날짜·묶음] [근무] [수]"다. 예: "평일마다 오픈 2명", "리더 태그 · 매일 · 오픈 1명 이상", "모든 사람 · 주마다 · 근무 시간 40시간 이하", "매일 오픈·미들 3명 이상"
- 해석 결과는 `lib/wording.ts`가 식에서 만든 문장이다. LLM이 쓴 문장을 쓰지 않는다. 조건이 있으면 "[범위]마다, [조건]이면 [지킬 것]" 틀이다. 예: "매일, 신입 태그가 마감에 1명 이상이면 리더 태그도 마감 1명 이상", "매일 김OO·이OO 마감 1명 이하"
- **조정 가능한 값**은 해석 결과 안에서 밑줄(`underline decoration-dotted underline-offset-2`)로 보인다. [수정]을 누르면 카드 안에 값마다 label + 숫자 입력이 펼쳐지고 [저장] / [취소]가 생긴다. 식 구조는 고치지 않는다(바꾸려면 말로 다시 입력)
- **예시 판정**: 해석 결과 아래에 "이런 근무면 이 규칙에 어긋나요" 한 줄과 작은 근무 띠(직원 이름 + 날짜 3~7칸의 근무 셀, 어긋난 칸은 `ring-1 ring-[#B42318]`)를 최대 3개 둔다. 대기 카드는 펼쳐 두고, 적용된 카드는 [예시 보기] Text로 접는다. 예시가 없으면 이 영역을 숨긴다
- 휴가 카드는 반드시/가능하면 토글을 보이지 않는다(항상 반드시).
- **설정 변경 카드**: 같은 목록에 `근무 형태` 배지로 둔다. 내용은 "근무 코드 추가 · P 피크 · 11:00~14:00 · 3시간"처럼 쓴다. 새 코드를 쓰는 규칙 카드는 바로 아래에 `pl-4`로 들여 놓고, 그 카드의 [적용] 옆에 "근무 코드 P 추가가 함께 적용돼요" 한 줄을 둔다. 설정 카드를 삭제하면 딸린 카드도 지운다
- **카드 순서는 바뀌지 않는다.** 적용해도 카드는 제자리에서 배지와 버튼만 바뀐다. 새 카드는 목록 맨 위에 붙는다.

### 제안 카드
제목 + `검증됨` 배지, 설명 한 줄(바꾸는 것: "최대 연속 근무 5 → 6", "이번 근무표에서만 끄기", "반드시 → 가능하면"), 검증 결과(`text-xs text-[#66665E]`, 예: "이렇게 바꾸면 근무표를 만들 수 있어요 · 희망 반영 14/16"), 오른쪽 아래 [무시] Text + [수락] Primary. 재풀이로 검증되지 않은 제안은 보여주지 않는다.

### 스테퍼
- 위치: 근무표 작성 화면의 제목 아래. 상단 바에는 두지 않는다. 확정 근무표에는 두지 않는다.
- 이미 지난 단계는 `<button>`으로 눌러 돌아갈 수 있다. 아직 오지 않은 단계는 비활성이다.
- 완료: `size-[22px] rounded-full bg-[#E3F0F3] text-[#155E75]` 안에 체크 SVG, 레이블 `text-[#3D3D38]`
- 현재: `bg-[#155E75] text-white` 숫자(mono), 레이블 `font-semibold text-[#1B1B18]`, `aria-current="step"`
- 단계 사이: `w-6 h-px bg-[#C9C9C1]`

### 근무 셀
```
relative w-[30px] h-7 rounded-xs inline-flex items-center justify-center font-mono text-[13px] font-semibold border border-transparent
+ 근무 코드 색상
고정:      오른쪽 위 자물쇠 SVG (absolute top-px right-px size-[9px])
변경됨:    shadow-[inset_0_0_0_2px_#D97706]
선택·편집: outline-2 outline-[#155E75] outline-offset-1
```
- 셀은 `<button>`으로 만들고 `aria-label="{이름} {M}월 {D}일 {코드}"`. 기간이 월 경계를 넘을 수 있으므로 월을 날짜마다 계산한다.
- 행 그리드: `grid-cols-[150px_repeat(N,30px)_repeat(K,34px)_repeat(2,44px)] gap-x-0.5`, N은 기간 길이(7~31), K는 활성 근무 코드 수(기본 4), 행 간격 2px
- 표 하단에 날짜별 근무조 합계 행(복합 코드는 세는 근무조마다 더한다), 오른쪽에 개인별 코드 합계 열과 누적 부담 열 2개(최근 4주 마감, 주말)
- 날짜 헤더가 달의 1일이면 `M/1`로 월을 함께 쓴다.
- **지난 날짜**: 운영 중인 기간에서 오늘 이전 칸은 고정 자물쇠를 표시하고 눌러도 편집되지 않는다. 오늘 열 머리에는 `border-b-2 border-[#155E75]` 밑줄을 긋는다.

### 반복 사용 컴포넌트
- **꺼진 규칙·요청 카드**
  - 원문과 해석 결과를 보조 색(`text-[#66665E]`)으로 낮춘다. 읽을 수 있어야 하므로 비활성 컨트롤 색은 쓰지 않는다.
  - `이번 근무표에서 꺼짐` 배지와 [다시 켜기] Text 버튼을 둔다.
  - 매장 조건 탭에서는 꺼짐이 보이지 않는다. 꺼짐은 그 근무표에만 있다.
- **제외된 직원**(휴직·퇴사)
  - 명단 표에서 이름을 `text-[#66665E]`로 하고 `제외` 배지를 붙인다.
  - 기본으로 접어 두고 "제외된 직원 1명 보기" Text 버튼으로 펼친다.
  - 행의 동작은 [근무표에서 빼기] / [다시 넣기]다. 빼도 지난 근무표와 통계에는 남는다고 버튼 근처에 한 줄로 쓴다.
  - [삭제]는 한 번도 근무표에 들어간 적 없는 직원에게만 보이고, 행 끝 메뉴 안에 둔다. [근무표에서 빼기]와 나란히 두지 않는다.
- **지난 근무 마지막 며칠 표**
  - 근무 셀 그리드를 재사용한다. 열은 지난 근무표 마지막 날들이고, 표 위에 "지난 근무표에서 가져왔어요. 마감 다음 날 오픈 금지 같은 규칙이 근무표 사이에서도 지켜지게 써요" 보조 텍스트를 둔다.
  - 셀은 `<div>`로 만들고 편집하지 않는다.
  - 첫 근무표처럼 지난 확정 근무표가 없으면 접힌 붙여넣기 입력을 쓴다(근무표 작성 ① 가능 시간의 준비 요약).
- **최근 4주 부담**
  - 그리드 오른쪽 열과 통계 표 열 이름은 "최근 4주 마감", "최근 4주 주말"이다. mono 숫자.
  - 최근 4주 기록이 하나도 없으면(첫 근무표) 이 열들을 그리지 않는다.
  - 요약 지표 아래에 한 줄로 "최근 4주 마감이 많았던 3명은 이번 근무표에서 마감을 줄였어요"처럼 근거를 쓴다. 숫자가 없으면 쓰지 않는다.
- **배너**: 지난 근무 변경, 가능 시간 변경, 저장 실패, 근무표 주기 변경은 모두 기존 주의 배너(`bg-[#FDF0DC] border-[#F1D3A8] text-[#7A4506]`) 하나로 쓴다. 배너에 버튼은 최대 하나다.
- **저장 상태**: 상단 바 오른쪽, 계정 왼쪽에 `text-xs text-[#66665E]`로 둔다.
  - "저장됨 14:32"(mono 시각)
  - 실패: `text-[#B42318]` "저장 실패" + [다시 시도] Text
- **계정**
  - 이메일(`text-xs`) + 메뉴 버튼. 메뉴 항목은 [로그아웃], [내 매장 데이터 삭제] Danger
- **대화상자**
  - 데이터 삭제 확인에만 쓴다.
  - 배경 `fixed inset-0 bg-[#1B1B18]/40`, 본문은 카드 스타일 `w-full max-w-[440px] rounded-xl`에 "그림자" 절의 그림자. blur를 쓰지 않는다.
  - 제목(섹션 제목 스타일), 본문 한두 줄, 오른쪽 아래 버튼. Primary는 하나다.
  - 데이터 삭제는 2단계다. 첫 대화상자에서 [계속], 두 번째에서 매장 이름을 입력하고 [삭제](Danger 스타일을 Primary 자리에 둔다).
  - `role="dialog"`, `aria-modal="true"`, Esc로 닫고, 열릴 때 첫 버튼에 포커스를 둔다.

### 요약 지표
카드 안 가로 배치, 칸마다 `px-5 py-3.5 border-r border-[#E2E2DC]`. 레이블 `text-xs font-medium text-[#66665E]`, 값 `font-mono text-xl font-semibold text-[#1B1B18]`. "못 지킨 규칙" 값만 `text-[#A15C07]`.
- 칸: "결과"(`규칙을 모두 지켰어요` / `근무표 없음` 배지), "희망 반영"(예: 9/9, 아래에 "희망·기피 요청이 걸린 날 중 지킨 날" 보조 한 줄), "못 지킨 규칙"('가능하면' 규칙을 못 지킨 횟수), "최근 4주 마감 배려"(예: "이영희 6회 → 1회 · 강서연 5회 → 1회". 최근 4주 기록이 없으면 칸을 그리지 않는다)

## 상호작용 상태
버튼, 탭, 근무 셀, 토글은 아래 상태를 모두 가진다. 같은 종류의 컨트롤은 화면이 달라도 똑같이 동작한다.

| 상태 | 규칙 |
|---|---|
| 기본 | 버튼은 버튼답게 보인다. 레이블만 봐도 결과를 알 수 있다 |
| hover | 색만 바꾼다(`transition-colors duration-[120ms]`) |
| 눌림 | `active:` 상태에서 hover보다 한 단계 진하게 한다(Primary `active:bg-[#0B3F4E]`, Secondary·Text `active:bg-[#E2E2DC]`) |
| 포커스 | 키보드 포커스에만 `focus-visible:outline-2 focus-visible:outline-[#155E75] focus-visible:outline-offset-2`. 포커스 표시를 없애지 않는다 |
| 비활성 | 숨기지 않고 비활성 스타일로 둔다. **왜 못 누르는지** 버튼 옆이나 아래에 한 줄로 쓴다. 예: "필요 인원을 입력하면 다음으로 넘어갈 수 있어요" |
| 진행 중 | 레이블을 "만드는 중…", "읽는 중…", "저장 중…"으로 바꾸고 스피너 하나만 둔다. 진행 중에는 버튼을 비활성으로 해서 두 번 보내지 않게 한다 |
| 성공 | 결과가 놓일 자리에 보여 준다(카드 배지가 `적용됨`으로 바뀜, 근무표가 갱신됨, 저장 상태가 "저장됨 14:32"로 바뀜). 토스트는 쓰지 않는다 |
| 실패 | 버튼을 다시 누를 수 있는 상태로 되돌리고, 바로 아래에 무엇이 잘못됐고 무엇을 하면 되는지 쓴다 |
| 선택됨 | 채운 스타일(`bg-[#1B1B18] text-white`)과 `aria-pressed="true"`, 탭은 `aria-current="page"` |

## 움직임
- 상태 변화를 설명할 때만 움직인다. 카드가 생길 때(아래에서 8px 올라오며 나타남, 240ms), 칸이 바뀔 때(변경 테두리가 들어옴, 120ms), 단계가 넘어갈 때(새 단계 제목으로 포커스). 장식 애니메이션, 끝없는 루프, 호버 시 확대를 두지 않는다.
- **랜딩 히어로 시퀀스**만 예외다. 실제 컴포넌트(입력 바, 규칙 카드, `ScheduleGrid`)를 샘플 데이터로 렌더하고 CSS 전환으로 순서를 준다: 입력 바에 "마감 다음 날 오픈은 안 되게"가 타이핑됨(0.4~1.6s) → 규칙 카드가 올라옴(2.0s) → 근무표 칸이 행마다 왼쪽부터 채워짐(2.6s부터 칸마다 60ms) → "규칙을 모두 지켰어요" 배지(5.3s). 한 번 재생하고 멈추며 [다시 보기] Text로 다시 돌린다. 이미지나 영상으로 대체하지 않는다.
- `prefers-reduced-motion: reduce`면 모든 전환을 즉시로 바꾸고, 히어로 시퀀스는 끝 상태를 바로 보여 준다.

## 피드백과 오류
- **결과는 그 자리에서**: 동작의 결과는 누른 버튼 가까이에 보여 준다. 화면 위쪽 전역 알림으로 보내지 않는다. 예외는 상단 바의 저장 상태 하나다.
- **기다림**: 2초를 넘을 수 있는 작업(생성, 해석, 제안 검증)은 진행 중 상태를 보여 준다. 진행률을 알 수 없으므로 진행 막대는 쓰지 않는다.
- **오류 문구**: "무엇이 일어났는지 + 무엇을 하면 되는지" 두 부분으로 쓴다. 예: "해석하지 못했어요. 날짜를 '15~17일'처럼 다시 적어 주세요." 오류 코드나 영어 원문을 그대로 보여 주지 않는다.
- **되돌릴 수 있는 동작은 즉시**: 카드 삭제, 이번 근무표에서만 끄기, 근무표에서 빼기는 확인 없이 바로 하고, 그 자리에 되돌리기(다시 켜기, 다시 넣기)를 둔다.
- **되돌릴 수 없는 동작만 확인**: 내 매장 데이터 삭제는 대화상자로 확인한다. 대화상자의 버튼은 두 개까지다.
- **예방**: 틀릴 수 있는 입력은 고르게 한다(근무표 주기 select, 공휴일 달력, 태그 칩, 근무 코드 표). 자유 입력은 자연어 입력 바뿐이고(가능 시간은 드래그로 고른다), 그 결과는 항상 카드로 확인받는다.

## 문구
- **읽는 사람은 매니저다.** 개발과 솔버 용어를 화면에 쓰지 않는다. 엑셀이나 메신저로 근무표를 짜 온 사람이 처음 보고 이해할 말로 쓴다. 코드와 문서 안의 이름(`period`, `carry_over`, `hard` 등)은 그대로 두고 화면 문구만 바꾼다.
- **말투**: 해요체로 짧게 쓴다. 한 문장에 한 가지만 말한다.
- **같은 것은 같은 말로**: 화면마다 용어를 바꾸지 않는다.
- **숫자에는 뜻을 붙인다**: 표의 열 이름이나 지표 레이블만 보고 무엇을 센 숫자인지 알 수 있어야 한다. 약어(`4주 C`)를 쓰지 않는다.

| 쓰는 말 | 쓰지 않는 말 | 뜻 |
|---|---|---|
| 말로 | 매장 직원 근무표(제품 이름 자리), 앱, 서비스 | 제품 이름. 브라우저 탭 제목은 "말로 · 근무표", 화면 이름이 있으면 "{화면} · 말로" |
| 이렇게 읽었어요 | 해석 결과, 파싱 결과 | 규칙·요청 카드에서 원문 아래 해석 문장의 아이브로우 |
| 근무표, "11월 근무표", "11/2~11/15 근무표" | 기간, 이번 기간, 다음 기간, 이달 | 매장의 근무표 주기 하나(1주~한 달) |
| 다음 근무표 | 다음 기간 | 아직 시작하지 않은 근무표 |
| 근무표 주기: 한 달(1일~말일) / 1주 / 2주 / 4주 | 기간 단위, 달력 월 | 매장이 근무표를 새로 짜는 간격 |
| 매장 조건 | 설정, 제약 | 근무표가 바뀌어도 유지되는 규칙. 필요 인원은 따로 센다 |
| 가능 시간 | 가용 시간, availability | 직원이 링크로 입력한 근무할 수 있는 시간대 |
| 요청 | 이달 요청, 희망 | 이 근무표에만 적용되는, 매니저가 적는 휴가·희망·기피 |
| 지난 근무 마지막 며칠 | 이월 근무, 전월 근무 | 지난 근무표 끝부분의 근무 |
| 작성 중 / 확정 / 운영 중 | 초안, 저장, 완료 | 근무표의 상태. 운영 중은 오늘이 속한 확정 근무표 |
| 반드시 / 가능하면 | hard / soft, 필수 / 선택 | 규칙을 지키는 정도 |
| 못 지킨 규칙 | soft 위반 | '가능하면' 규칙을 지키지 못한 횟수 |
| 링크 복사 | 초대, 발송 | 공용 직원 링크를 복사해 매니저가 직접 공유하는 것 |
| 근무표 만들기 / 다시 만들기 | 생성, 풀이, 재풀이, 다시 풀어요 | 솔버를 돌리는 것 |
| 규칙을 모두 지켰어요 / 근무표 없음 | 해 있음 / 해 없음 | 생성 결과 |
| 규칙 만들기 / 요청 만들기 | 해석 | 자연어를 카드로 바꾸는 버튼 |
| 표로 만들기 | 변환, 반영 | 붙여넣은 지난 근무를 표로 바꾸는 버튼 |
| 적용 | 추가, 저장 | 규칙·요청 카드를 반영하는 것 |
| 수락 | 적용 | 검증된 완화 제안을 반영하는 것 |
| 근무표에서 빼기 / 제외 / 다시 넣기 | 비활성, 비활성으로, 활성, 삭제, 퇴사 | 휴직·퇴사한 직원을 새 근무표에서만 빼는 것 |
| 직원 12명 | 활성 12명 | 새 근무표에 들어가는 직원 수 |
| 근무 형태 | 근무 코드 설정, config, 구조 | 매장의 근무 코드와 시각 |
| 더블 | 복합 코드 | 하루에 두 근무조를 하는 근무 |
| 태그 | 라벨, 그룹 | 직원에 붙이는 말(리더, 신입 등) |
| 중요도 높음 / 보통 / 낮음 | 가중치, weight, priority | '가능하면' 규칙끼리 부딪칠 때 먼저 지킬 순서 |
| 휴무 | O, 오프(문장 안) | 근무 셀 글자는 O를 그대로 쓴다 |
| 최근 4주 마감 / 최근 4주 주말 | 4주 C, 4주 주말, 누적 부담 | 직전 4주의 확정 근무 수 |
| 평균보다 많은 근무일 (예: +2일, −1일) | 평균 대비 편차, -0.40 | 개인 근무일 수와 평균의 차이. 정수 일로 반올림 |

- **빈 상태**: 비어 있는 영역에는 무엇을 하면 채워지는지 한 줄과 그 동작 버튼을 둔다. 예: 지난 근무표 표가 비면 "확정한 근무표가 여기에 쌓여요".
- **내부 값 노출 금지**: 직원 id(`e01`), 제약 type 이름, 영어 오류 원문을 화면에 보여 주지 않는다.

## 접근성
- **대비** (WCAG 2.2 AA): 본문 텍스트 4.5:1, 큰 텍스트와 컨트롤 경계 3:1 이상. 이 가이드의 색 조합을 계산한 결과는 아래와 같다.
  - 통과: 주 텍스트·본문·보조(`#66665E` 5.8:1), 강조(`#155E75` 7.3:1), 시맨틱 배지 전부(5.6~7.0:1), 근무 코드 전부(4.6~12.9:1)
  - 정보 텍스트에 쓰지 않음: 비활성 컨트롤 색 `#9A9A91`(2.8:1)
  - 이번에 바꿈: placeholder `#8A8A80` → `#707068`(5.0:1), 입력 테두리 `#C9C9C1`(1.7:1) → `#8A8A80`(3.5:1)
- **색만으로 구분하지 않는다**: 근무 코드는 글자, 상태는 배지 글자, 변경된 칸은 테두리, 고정은 자물쇠로 함께 표시한다.
- **키보드**
  - 모든 동작은 Tab과 Enter/Space로 할 수 있다.
  - 스테퍼 단계를 옮기면 새 단계의 제목(`h2`, `tabIndex={-1}`)으로 포커스를 옮긴다.
  - 대화상자를 닫으면 연 버튼으로 포커스를 되돌린다.
- **상태 알림**: 진행 중, 결과, 오류 문구는 `role="status"`(오류는 `role="alert"`) 안에 두어 스크린 리더가 읽게 한다.
- **레이블**: 아이콘만 있는 버튼은 `aria-label`, 입력은 `<label>`을 쓴다. placeholder를 레이블 대신 쓰지 않는다.

## 레이아웃
- 전체 너비: `max-w-[1360px] mx-auto px-10`
- 정렬: 좌측 정렬 기본. 중앙 정렬 히어로 금지
- 간격: 카드 사이 `gap-5`~`gap-6`, 앱 화면 섹션 사이 `gap-6`, 카드 안 `gap-2.5`~`gap-3.5`
- 묶음: 관련된 입력과 버튼은 같은 카드 안에 붙여 둔다. 서로 다른 일은 카드를 나눈다. 카드 안의 간격은 카드 사이 간격보다 항상 좁다
- 위계: 화면마다 페이지 제목은 하나다. 화면을 위에서부터 읽으면 "지금 상태 → 할 일 → 결과" 순서가 되게 놓는다. 할 일 영역(강조 바탕 패널)은 한 화면에 하나다
- 앱 상단 바: 높이 60, `bg-white border-b border-[#E2E2DC]`. 왼쪽 워드마크(홈 링크) + 세로 구분선 + 매장 이름(`text-sm font-medium`) + 근무표 주기(`text-[13px] text-[#66665E]`, "1주 단위"). 오른쪽 저장 상태 + 계정(아바타 24 `bg-[#E3F0F3] text-[#155E75]` 성 한 글자 + 이메일 + 메뉴 화살표). 스테퍼는 두지 않는다
- 탭 줄: 상단 바와 같은 흰 띠 안, 높이 44, [근무표] [매장 설정]. 로그인 화면과 매장 준비에서는 숨긴다
- 근무표·통계 표는 `overflow-x-auto` 상자 안에 둔다. 표를 줄이거나 셀을 30px보다 작게 만들지 않는다
- 랜딩 페이지
  - 상단 바: 페이지 바탕색 위 `border-b`, 워드마크(19px) + 오른쪽 Text 링크 [문제] [동작 방식] [만든 방식] [GitHub] + [내 매장으로 시작하기] Primary(h-10)

  - 섹션: `py-24 border-t border-[#E2E2DC]`, 아이브로우 "01 · 문제" + 제목 32px + 설명 16px(`max-w-[640px]`)

  - 02 동작 방식: 세로 4줄(`grid-cols-[96px_5fr_6fr]`), 큰 숫자(mono 48 `#155E75`) + 제목 20px + 본문 + 오른쪽 화면 조각(가능 시간 캘린더, 입력 바, 요약 지표, 운영 중 변경)
  - 03 만든 방식: 3열 카드(말 · 계산 · 검증) + 번역 정확도 한 줄(수치가 없으면 자리표시) + GitHub 링크. 데모 GIF 섹션은 두지 않는다(히어로가 대신한다)
  - CTA 띠: 강조 면(`bg-[#155E75] py-[72px]`), 왼쪽 32px 제목 두 줄 + 보조, 오른쪽 흰 버튼 [내 매장으로 시작하기] + 테두리 버튼 [데모 영상 보기]
  - 푸터: 회색 마크 + "말로 · 포트폴리오 프로토타입", 개인정보처리방침·GitHub 링크
  - 장식 이미지나 근거 없는 수치·후기를 넣지 않는다. 문구는 앱과 같은 "문구" 표를 따르고, 기술 설명은 "만든 방식" 섹션 하나에만 둔다(PRD 핵심 기능 9)
- 데모 영상 대화상자(`components/DemoVideo.tsx`, ADR-022): 어두운 배경 위 `cardXl` + 그림자, `max-w-[1120px] p-4`. 머리줄은 "데모 영상" 제목 + 보조 한 줄("실제 화면이에요. 직원 링크 → 매장 조건 한 줄 → 근무표 → 확정까지 1분 안에 보여요.") + [닫기] Text. 아래 `<video controls autoplay>`(16:10, `public/demo.mp4`). 열리면 [닫기]에 포커스, Esc로 닫고, 닫히면 연 버튼으로 포커스를 되돌린다(`role="dialog"`, `aria-modal`)

## 아이콘
- SVG 인라인, `stroke="currentColor"`, strokeWidth 1.5~1.8, 크기 12~14px
- 아이콘 컨테이너(둥근 배경 박스)로 감싸지 않는다 (스테퍼 단계 원은 예외)
- 이모지를 쓰지 않는다. 고정 표시는 🔒 대신 자물쇠 SVG
- 장식용 SVG는 `aria-hidden="true"`, 아이콘만 있는 버튼은 `aria-label`
