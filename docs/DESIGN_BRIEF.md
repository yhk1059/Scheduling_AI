# 디자인 브리프: 말로

디자인 재설계(Claude Design 시안 → UI_GUIDE 갱신 → phase `8-design` 구현)의 결정 기록이다. 시안: 말로 디자인 시안(Claude Design, 비공개) (2026-11-01 승인). "디자인 원칙"과 "유지하는 것"은 `docs/UI_GUIDE.md`로 옮겼고, 구현 규칙은 UI_GUIDE가 우선한다. 이 문서는 왜 그렇게 정했는지를 남긴다.

## 왜 다시 하나
지금 화면은 UI_GUIDE의 "장식 없음, 무채색, 정보 밀도 우선"을 그대로 구현한 결과다. 규칙은 지켰지만 완성도가 "절제"가 아니라 "성의 없음"으로 읽힌다.
- 제품에 이름이 없다. 상단 바와 아이브로우가 "매장 직원 근무표"라는 설명문이고 워드마크가 없다.
- 랜딩이 제품의 핵심 순간(말 한 줄 → 규칙 카드 → 근무표)을 보여 주지 않는다. 히어로 우측은 정지한 카드 2장과 표 일부, 데모 GIF는 자리표시다. 문제 6장·동작 방식 4장이 같은 모양의 카드 격자라 눈이 멈출 곳이 없다.
- 샘플 데모가 규칙 카드 7장 벽으로 시작한다. 주인공인 근무표는 스크롤 아래에 있다.
- 타이포 위계가 평평하다. 앱 전체가 13~15px, 페이지 제목이 22px이라 "지금 할 일"이 튀지 않는다.
- 문구(해요체, 매니저 용어 표, 빈 상태)는 이미 좋다. 바꿀 것은 문구의 리듬과 배치다.

## 제품 이름
**말로**. "말로 짜는 근무표". 제품의 원리가 이름이다.
- 워드마크: 한글 2글자. 상단 바 왼쪽, 로그인 카드, 랜딩 아이브로우, 직원 입력 화면 맨 위, 브라우저 탭 제목(`말로 · 근무표`)에 쓴다.
- 코드와 문서 안의 식별자(`nurse-scheduler`, 디렉토리명)는 바꾸지 않는다. 화면 문구와 `metadata.title`만 바꾼다.

## 사용자와 디자인 요구
| 사용자 | 상황 | 디자인이 해 줘야 하는 것 |
|---|---|---|
| **매니저** (주 사용자, 카페·음식점 점장) | 저녁에 PC로, 바쁜 와중에 짠다. 엑셀은 익숙하고 개발 용어는 모른다. 원하는 건 "빨리, 실수 없이, 직원에게 댈 근거" | 밀도는 유지하되 위계가 분명할 것. 근무표가 항상 주인공일 것. 지금 할 일이 한눈에 보일 것 |
| **직원** (링크 입력) | 카톡 링크를 열어 1분 안에 드래그하고 나간다 | 어느 매장의 어느 주인지 크게. 안내는 한 줄. 칠하는 동작이 기분 좋을 것 |
| **포트폴리오 방문자** | 30초 안에 "이 사람이 뭘 만들 수 있나"를 판단한다 | 첫 화면에서 핵심 순간이 움직일 것. 워드마크·타이포·디테일 같은 완성도 신호. "만든 방식"이 짧고 설득력 있을 것 |

## 디자인 원칙 (UI_GUIDE "디자인 원칙"을 대체한다)
1. **근무표가 주인공이다.** 어느 화면이든 가장 크고 선명한 것은 근무표이거나 그것을 만드는 입력이다. 랜딩 첫 화면과 샘플 데모는 근무표로 시작한다. 규칙 카드 목록은 근무표 다음이다.
2. **말이 인터페이스다.** 자연어 입력 바는 화면의 중심 요소다. 여느 입력창보다 크고(높이 48px 이상), 예시 문장이 보이고, 결과 카드는 "내 말이 이렇게 읽혔다"는 답장처럼 원문 인용과 해석을 시각적으로 잇는다.
3. **위계가 먼저, 밀도는 그다음.** 화면의 내용을 "지금 할 일 / 확인할 것 / 접어둔 것" 세 단계로 나누고, 타이포 스케일과 여백으로 구분한다. 스케일은 페이지 제목 28 · 섹션 18 · 본문 14 · 보조 12(px)를 기준으로 시안에서 확정한다. 표 안 글자는 13을 유지한다.
4. **색은 뜻이 있을 때만, 대신 과감하게.** 근무 코드(A/M/C/O)와 상태(성공·오류·주의·변경)에만 색을 쓴다. 강조색은 하나지만 브랜드 표면(워드마크, Primary, 현재 단계, 칠한 가능 시간, 선택된 칸)에는 면으로 쓴다. 링크와 작은 텍스트에만 쓰는 지금 방식은 버린다.
5. **장식 히어로는 금지, 제품 히어로는 허용.** 일러스트, 배경 도형, 스톡 이미지는 두지 않는다. 실제 제품 화면이 움직이는 장면이 장식 역할을 한다. 그림자는 떠 있는 것(메뉴, 대화상자, 드래그 중인 요소)에만 쓴다. 카드는 테두리로 구분한다.
6. **결정은 사람이 한다.** LLM이 해석한 결과는 항상 카드로 제안되고, [적용]이나 [수락]을 누르기 전에는 근무표에 반영되지 않는다. (유지)
7. **되돌릴 수 있는 동작은 묻지 않는다.** 바로 하고 되돌리는 버튼을 둔다. 되돌릴 수 없는 동작만 확인을 받는다. (유지)
8. **움직임은 상태 변화를 설명할 때만.** 카드가 생길 때, 칸이 바뀔 때, 단계가 넘어갈 때 120~240ms. 장식 애니메이션과 끝없는 루프는 두지 않는다(랜딩 히어로 시퀀스는 예외이며 한 번 재생 후 [다시 보기]). `prefers-reduced-motion`이면 즉시 전환한다.

## 유지하는 것
- UI_GUIDE "AI 슬롭 안티패턴" 표 전부(blur, 그라데이션 텍스트, "Powered by AI" 배지, 글로우, 보라색, 균일한 rounded-2xl, 배경 orb).
- UI_GUIDE "문구" 표(쓰는 말 / 쓰지 않는 말)와 해요체, "읽는 사람은 매니저다".
- 근무 코드 색과 "글자를 항상 함께 표시한다". 색만으로 구분하지 않는다. 휴무 칸만 글자 없이 비운다.
- 접근성 기준(WCAG 2.2 AA 대비, 키보드, `role="status"`, 레이블).
- 상호작용 상태 표(hover·눌림·포커스·비활성·진행 중·성공·실패·선택됨). 비활성 버튼 옆의 "왜 못 누르는지" 한 줄.
- 피드백과 오류 규칙(결과는 그 자리에서, 토스트 없음, 오류는 "무엇이 + 무엇을 하면").
- 화면 구조와 이동(탭, 스테퍼, 상태로 화면이 정해지는 규칙), 각 화면의 정보 항목. 바꾸는 것은 배치·크기·순서다.
- 데스크톱(1280px 이상) 전용, 라이트 테마.

## 화면별 방향
| 화면 | 지금 | 방향 |
|---|---|---|
| 상단 바 | 텍스트 앱 이름 + 매장 이름 | 워드마크 "말로" + 매장 이름·주기. 저장 상태와 계정은 유지 |
| 랜딩 첫 화면 | 좌 텍스트, 우 정지 카드 2장 + 표 | 좌 텍스트(제목 48px 이상, 한 줄 가치 제안, 버튼 2개), 우 애니메이션: 입력 바에 "마감 다음 날 오픈은 안 되게"가 타이핑됨 → 규칙 카드가 생김 → 근무표 칸이 채워짐. 한 번 재생 후 [다시 보기] |
| 랜딩 문제·동작 방식 | 같은 모양 카드 6장 + 4장 | 문제는 "전/후" 한 쌍으로 묶어 3줄(메신저 캡처 느낌의 전 ↔ 제품 화면의 후). 동작 방식은 숫자 큰 4단계를 세로로, 각 단계 옆에 실제 화면 조각 |
| 랜딩 데모·만든 방식 | GIF 자리표시 + 긴 문단 | 데모 섹션은 삭제(히어로가 대신한다). 만든 방식은 3열: "말은 LLM이 / 계산은 솔버가 / 검증은 재풀이로" + 번역 정확도 수치 한 줄 |
| 샘플 데모 | 제목 → 규칙 카드 7장 → 근무표 | 제목 → 근무표(4주 전체, 통계 포함) → 규칙 카드. 상단에 "모두에게 같은 화면이에요" 한 줄과 [내 매장으로 시작하기] |
| 로그인 | 작은 카드 하나 | 워드마크 + 한 줄 설명 + [Google로 로그인] + 샘플 링크. 카드는 더 크고 가운데 |
| 매장 홈 | 카드 3개가 같은 무게 | "지금 할 일" 카드를 가장 크게, 진행 단계가 한 줄로 보이고 Primary 하나. 운영 중 카드는 그 위에 얇게, 지난 근무표는 표 |
| 근무표 작성 ③ | 접힌 예외 입력 → 버튼 → 표 | 입력 바를 크게 위에. 요약 지표는 근무표 바로 위에 한 줄. 근무표는 가로 폭을 다 쓰고 셀은 30px 유지 |
| 확정 근무표 | 작성 ③과 거의 같음 | 변경 입력 바가 첫 요소. 바뀐 칸 요약은 입력 바 바로 아래 |
| 직원 가능 시간 입력 | 이름 버튼 목록 → 캘린더 | 맨 위에 워드마크 작게 + 매장·직원 이름 작은 제목. 이름 버튼은 큰 칩. 캘린더는 칠한 칸이 강조색 면, 드래그 중 그림자. 하단 [제출]은 고정 줄 |

## 시안 작업 (Claude Design)
Design 아티팩트 타입을 쓰고, 디자인 시스템은 새로 만든다(UI_GUIDE에 링크된 간호사 시절 시안은 참고만 한다).
1. **디자인 시스템 보드**: 워드마크, 타이포 스케일, 색 토큰, 간격, 버튼·입력·카드·배지·스테퍼·근무 셀·규칙 카드·자연어 입력 바.
2. **화면 보드** (1440px 아트보드): 랜딩 전체, 샘플 데모, 로그인, 매장 홈, 근무표 작성 ③, 확정 근무표, 직원 가능 시간 입력.
3. 피드백 2~3회 반복. 문구는 시안에서 같이 확정한다.
4. 확정되면 `docs/UI_GUIDE.md`의 "디자인 원칙", "색상", "컴포넌트", "레이아웃", "타이포그래피"를 시안 값으로 다시 쓴다.

## 구현 제약 (phase `8-design`에서 지킨다)
- 스택은 그대로: Next.js App Router, Tailwind CSS 4, 컴포넌트 규격 클래스는 `components/ui.ts`에 모은다. UI 라이브러리와 애니메이션 라이브러리를 추가하지 않는다.
- 히어로 애니메이션은 실제 컴포넌트(`ScheduleGrid`, 규칙 카드)를 샘플 데이터로 렌더하고 CSS 전환으로 순서를 준다. 이미지나 영상으로 대체하지 않는다.
- 화면의 정보 항목과 동작은 PRD·UI_GUIDE "화면 구조"를 따른다. 디자인 phase에서 기능을 더하거나 빼지 않는다.
- UI는 TDD 대상이 아니다. AC는 `npm run build && npm run lint && npm run test:e2e`이고, step마다 수동 저니 체크리스트를 둔다.
