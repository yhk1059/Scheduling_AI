# PRD: 간호사 근무표 (LLM + CP-SAT)

## 목표
수간호사가 말로 설명한 규칙과 요청으로 근무표를 만들고, 막히는 이유와 변경 영향을 설명받게 한다. 매주 또는 매달 반복해서 쓸 수 있어야 한다.
- 판매용 제품이 아니라 LLM 활용 빌드 역량을 보여주는 포트폴리오 프로토타입이다.
- 다만 데모에서 끝나지 않고 실사용자가 기간을 넘어 반복해서 쓸 수 있는 수준을 목표로 한다. 저장, 로그인, 기간 간 이월을 포함한다.
- 계산은 CP-SAT 솔버가 하고, LLM은 번역과 설명만 맡는다.

## 사용자
- **주 사용자: 수간호사 1명, 병동 1개.**
  - 예: 내과 병동, 로테이션 인원 15명, 3교대
  - 병동마다 근무표 주기가 다르다. 월 단위로 짜는 병동도 있고, 1주·2주·4주 단위로 새로 짜는 병동도 있다.
  - 지금은 엑셀과 머릿속 규칙으로 짜고, 매번 며칠씩 걸린다.
  - 엑셀은 능숙하다. 설정 화면은 싫어하고 말로 설명하는 게 편하다.
  - 수간호사 본인(상근 Day)은 로테이션 명단에 넣지 않는다.
- **보조 사용자: 포트폴리오 방문자.** 로그인하지 않고 샘플 데모(보기 전용)를 둘러본다.

| 페인 포인트 | 해결 기능 |
|---|---|
| 규칙이 머릿속에만 있다 | 자연어 → 규칙 카드 |
| 요청이 다 안 들어가는데 어디서 막히는지 모른다 | 충돌 설명과, 재풀이로 검증된 완화 제안 |
| 확정 후 병가가 생기면 전체를 다시 짠다 | 최소 변경 재스케줄 |
| "왜 나만 주말이 많아요?"에 근거를 대기 어렵다 | 개인별 통계와 누적 부담 |
| 매번 명단, 규칙, 지난 기간 마지막 근무를 다시 옮겨 적는다 | 저장된 병동과 자동 이월 |
| 지난번에 나이트를 많이 한 사람을 이번에 배려하기 어렵다 | 최근 4주 누적 부담을 공정성에 반영 |

## 데이터 층
수명이 다른 세 층으로 나눈다.

| 층 | 내용 | 수명 |
|---|---|---|
| **병동** | 명단(고정 id, 활성/비활성), 필요 인원, 병동 규칙, 기간 단위 | 계속 유지되고 가끔 수정 |
| **기간** | 날짜 범위, 공휴일, 요청, 근무표, 상태(초안/확정), 확정본 버전 | 기간마다 새로 만든다 |
| **이력** | 지난 기간의 확정본 | 쌓인다. 다음 기간의 이월과 누적 부담에 쓴다 |

- **기간 단위**: 병동마다 하나로 고정한다(1주 / 2주 / 4주 / 달력 월). 주 단위 기간은 월요일에 시작한다.
- **간호사 id**: 한 번 정하면 다시 매기지 않는다. 명단을 고치거나 순서를 바꿔도 요청과 고정 배정이 다른 사람에게 옮겨 가지 않는다.
- **기간 분리**: 기간마다 데이터가 분리된다. 다른 기간의 날짜, 고정 배정, 확정본이 섞이지 않는다.

## 화면
- **랜딩**(`/`): 소개 페이지. [샘플로 체험하기]는 샘플 데모로, [내 병동으로 시작하기]는 앱으로 간다.
- **샘플 데모**(`/demo`): 모든 방문자에게 똑같이 보이는 보기 전용 화면(J7). 앱과 저장소를 공유하지 않는다.
- **앱**(`/app`)
  - 시작 화면: 병동이 없을 때 보인다. 게스트는 탭 줄의 [시작 화면]으로 다시 열 수 있다.
  - 처음 설정: 근무표를 한 번도 만들지 않은 병동에서만 보이는 안내 단계(병동·명단 → 필요 인원 → 병동 규칙)
  - 병동 홈([근무표] 탭): 운영 중인 기간, 다음 기간 상태, 최근 기간 목록
  - 병동 설정: 명단, 필요 인원, 병동 규칙, 기간 단위. 처음 설정을 마친 뒤 고칠 때 쓴다
  - 근무표 작성: 확정 전 기간. 요청(준비 요약 포함) → 근무표(생성, 해 없음, 조정) → [확정]
  - 확정 근무표: 확정한 기간. 운영 중 변경, 다시 확정, CSV. 끝난 기간은 보기 전용
  - 기간을 열면 상태로 화면이 정해진다(초안 → 근무표 작성, 확정 → 확정 근무표).
- 화면 배치의 세부는 UI_GUIDE에서 정한다.
- 이 문서의 기간, 이월, 초안, 비활성, hard/soft는 데이터 용어다. 화면에는 UI_GUIDE "문구" 표의 말(근무표, 지난 근무 마지막 며칠, 작성 중, 제외, 반드시/가능하면)로 쓴다.

## 사용자 저니
- 기준 인물: 내과 병동 수간호사, 15명, 3교대, 월 단위
- 변형 인물: 응급실 수간호사, 2주 단위
- 사용 사이클: 다음 기간이 시작하기 2~3주 전에 요청을 모으고, 1주 전에 확정·공지한다. 운영 중에는 수시로 수정한다.

### J0. 발견과 첫 진입 (방문자, 수간호사)
- 생각: "우리 병동 규칙으로도 짤 수 있나? 매번 다시 입력해야 하나?"
- 흐름: 랜딩 → [샘플로 체험하기] 또는 [내 병동으로 시작하기] → 샘플 데모(J7) 또는 처음 설정(J1)
  - [내 병동으로 시작하기]: 로그인 상태이거나 이 브라우저에 게스트 입력이 있으면 그 병동으로 들어간다. 없으면 빈 병동을 만든다.
  - `/app`을 바로 열면 시작 화면에서 고른다.
  - 로그인 상태이거나 이 브라우저에 게스트 입력이 있으면 시작 화면 없이 바로 들어간다. 근무표를 한 번도 만들지 않았으면 처음 설정의 아직 끝나지 않은 첫 단계, 아니면 마지막 화면.
  - 시작 화면에서는 [샘플로 체험하기](샘플 데모로 이동), [내 병동으로 시작하기], [Google로 로그인] 중에서 고른다.
  - 게스트가 탭 줄의 [시작 화면]을 누르면 시작 화면에 [이어서 하기]도 보인다. 새로 시작을 고르면 기존 입력을 지운다는 확인을 받는다.
- 끝: 샘플 데모 또는 처음 설정 ①(게스트)

### J1. 병동 설정 (처음 한 번, 이후에는 가끔)
- 생각: "엑셀에 있는 명단을 그대로 쓰고 싶다. 규칙은 말로 하는 게 편하다."
- 처음에는 처음 설정 화면이 한 단계씩 안내한다. 단계마다 [다음]으로 넘어가고 [이전]으로 돌아갈 수 있다.
  1. 병동·명단: 병동 이름, 기간 단위, 명단. 활성 간호사가 1명 이상이어야 [다음]
     - 명단 표에 이름, 연차, 나이트 전담을 한 명씩 직접 적는다. 표 맨 아래 입력 줄에서 Enter나 [추가]로 더한다. 파일 올리기와 붙여넣기는 없다.
     - 이름 입력란에 "이니셜을 써도 됩니다"를 안내한다.
  2. 필요 인원(평일 / 주말·공휴일): 필수 입력이다. 모두 채워야 [다음]
     - 근무조·요일 종류마다 숫자 하나를 받는다. 날마다 정확히 그 인원을 배정한다(최소·최대 범위는 받지 않는다).
     - 범위가 필요하면 병동 규칙에 말로 적는다(예: "평일 데이는 3~4명").
  3. 병동 규칙: "나이트 다음 날은 무조건 쉬게"를 입력하면 규칙 카드가 생긴다. 이 단계의 끝 버튼이 [첫 근무표 만들기]다.
     - 카드에는 원문, hard/soft 토글, 적용/수정/삭제 버튼이 있다.
     - 입력이 모호하면 되묻고, 지원하지 않는 규칙이면 그렇다고 안내한다.
     - 적용한 규칙이 0개여도 진행할 수 있다. 이때는 필요 인원만 지킨다고 안내하고, 적용하지 않은 카드가 남아 있으면 그 카드는 빠진다고 안내한다.
- 처음 설정 도중에 나갔다가 들어오면 아직 끝나지 않은 첫 단계에서 다시 연다.
- 규칙
  - 첫 기간을 만든 뒤에는 처음 설정이 다시 보이지 않는다. 고칠 때는 병동 설정을 쓴다.
  - 병동 설정은 기간과 분리된 영역이다. 언제든 다시 들어와 고칠 수 있다.
  - 고친 내용은 다음에 생성하는 기간부터 적용된다. 이미 확정된 기간은 바뀌지 않는다.
- 끝: [첫 근무표 만들기] → 근무표 작성(J2)

### J2. 첫 기간 작성 (게스트도 가능)
- 생각: "정말 쓸 만한 근무표가 나오나?"
- 근무표 작성은 두 단계다. 확정은 단계가 아니라 ②의 끝 버튼이다.
  1. 요청
     - 맨 위에 준비 요약 한 줄: 기간(기본값은 오늘 이후 첫 기간), 공휴일 수, 간호사 수, 이월 근무. [바꾸기]로 펼친다.
       - 펼치면 날짜 범위, 공휴일 체크, 명단 확인, 이월 근무가 있다.
       - 첫 기간에는 지난 근무 마지막 며칠을 직접 붙여넣을 수 있다(선택).
     - 이번 기간 요청: "이영희 15~17일 휴가"를 입력하면 요청 카드가 생긴다.
     - 이 기간에 적용되는 병동 규칙을 접힌 목록으로 보여 준다.
  2. 근무표
     - 생성: 근무표, 요약(희망 반영 수, soft 위반), 개인별 통계를 보여준다.
     - 해가 없을 때: 충돌 설명과, 재풀이로 검증된 완화 제안을 보여준다.
       - 제안을 [수락]하면 재풀이한다.
       - 제안이 없거나 LLM이 실패하면 [이번 근무표에서만 끄기]를 쓴다. 이 기간에만 적용되고, 카드에 꺼짐 상태가 보이며, 다시 켤 수 있다.
     - 조정: 칸을 수정하고 🔒 고정한 뒤 재풀이한다.
     - [확정]하면 확정 근무표 화면으로 옮겨 간다.
- 게스트도 확정할 수 있다. 로그인은 흐름을 막지 않는다.
  - 확정하면 그 자리에 "확정했어요. 이 브라우저에만 저장돼 있어요"와 [Google로 로그인]을 보여 준다(주의 배너, 버튼 하나).
  - 로그인하면 게스트 데이터를 내 병동으로 옮긴다. 확정 기록은 그대로 유지된다.
  - 로그인하지 않아도 다음 기간 만들기, 운영 중 변경까지 이 브라우저 안에서 모두 할 수 있다.
- 끝: 확정된 기간 1개(확정 근무표 화면), CSV

### J3. 다음 기간 작성 (반복 사용의 핵심)
- 생각: "지난번 설정 그대로, 이번 요청만 넣고 싶다. 지난번에 나이트를 많이 한 사람은 이번에 덜 하게."
- 흐름: 재방문하면 병동 홈이 열린다(로그인했으면 서버에서, 게스트면 이 브라우저에서 불러온다).
  - 병동 홈: 운영 중인 기간(확정), 다음 기간 상태(없음 / 초안 / 확정), 최근 기간 목록
  - [다음 근무표 만들기] → 근무표 작성 ① 요청
    1. 날짜 범위를 자동으로 계산한다.
    2. 명단 점검: 지난 확정 기간 이후 추가·비활성화된 간호사를 준비 요약에 보여 준다. 입사자 추가와 퇴사·휴직자 비활성화는 병동 설정에서 한다.
    3. 이월 확인: 지난 확정본의 마지막 며칠을 자동으로 채운다.
    4. 준비 요약은 접혀 있다. 명단이 지난 확정 기간과 다르거나 지난 기간이 바뀌어 이월이 달라졌을 때만 저절로 펼친다.
    5. 병동 규칙은 그대로 적용된다. 이번 기간에만 다른 규칙은 요청 단계에서 입력한다.
    6. 요청 입력 → [다음] → 생성 → 조정 → [확정]
- 결과에 누적 부담 근거를 보여 준다. 예: "지난 4주 나이트 6회 → 이번 기간 2회"
- 끝: 다음 기간 확정, 이력 1개 추가

### J4. 운영 중 변경 (수시)
- 생각: "확정 공지는 이미 나갔다. 바꾸는 칸은 최소로 하고, 이미 지난 날은 건드리면 안 된다."
- 흐름
  1. 병동 홈 → 운영 중 카드의 [변경 입력] → 확정 근무표 화면(변경 입력 바에 포커스)
  2. "최지훈 이번 주 병가"를 입력하고 카드를 [적용]한다.
  3. 최소 변경으로 재스케줄하고, 변경된 칸을 하이라이트한다.
  4. [다시 확정]. 다시 확정하기 전에는 [변경 취소]로 마지막 확정본(배정과 요청)으로 되돌릴 수 있다.
- 규칙
  - 오늘 이전 날짜는 자동으로 고정되어 바뀌지 않는다.
  - 확정한 뒤에는 요청 단계로 돌아가지 않는다. 시작 전에 확정한 기간도 늦게 온 요청을 변경 입력으로 넣는다.
  - 끝난 기간(오늘이 기간 뒤)은 보기 전용이다. 변경 입력을 두지 않는다.
  - [다시 확정]할 때마다 확정본 버전(시각, 바뀐 칸)을 남긴다. 버전을 비교하거나 복원하는 화면은 두지 않는다.
- 연쇄 영향: 이 기간이 바뀌어 다음 기간의 이월이 달라지면 "지난 근무표가 바뀌어 이어지는 근무가 달라졌어요" 배너를 띄운다. 다음 기간이 초안이든 확정이든 같다. 이월은 다음에 생성할 때 다시 계산한다.

### J5. 명단 변동 (입사, 퇴사, 장기 휴직)
- 생각: "퇴사한 사람이 지난 근무표에서 사라지면 안 된다."
- 규칙
  - 간호사는 삭제하지 않고 비활성으로 둔다.
  - 비활성 간호사는 이력과 통계에는 남고, 새 기간 생성에서는 빠진다.
  - id는 다시 매기지 않는다.

### J6. 공용 PC와 데이터 삭제
- 로그아웃하면 이 브라우저에 남은 병동 데이터를 지운다.
- [내 병동 데이터 삭제]는 서버의 병동 데이터를 모두 지운다(확인 2단계). Google 계정 연결 자체는 남는다.

### J7. 샘플 데모 (방문자)
- 샘플은 모든 방문자에게 똑같이 보이는 보기 전용 데모다. 개인 데이터가 아니다.
  - 저장하지 않는다. 앱의 게스트 입력, 로그인, 서버와 관계가 없다.
  - 오늘 날짜에 맞추지 않는다. 운영 중, 다음 기간 같은 상태도 없다. 미리 만들어 둔 한 달 근무표 하나만 보여 준다.
  - API를 부르지 않는다. 조작할 수 없다.
- 보여 주는 것
  - 명단 15명(나이트 전담 2명 포함), 필요 인원, 병동 규칙 6개(나이트 다음 날 휴무, 최대 연속 근무, 최대 연속 나이트, 기간당 최소 휴무, 나이트·주말 공정성). 규칙은 말로 적은 원문과 규칙 카드로 보여 준다.
  - 이 규칙을 모두 지키는 한 달 근무표와 개인별 D/E/N/O 수. 나이트 전담도 휴무를 받는다.
- 끝: [내 병동으로 시작하기] → 앱(J0)

### J8. 실패와 예외
- LLM 장애: 규칙 카드를 직접 수정하거나 [이번 근무표에서만 끄기]로 진행할 수 있다.
- 저장 실패(네트워크): 브라우저에 보관하고 다시 시도한다고 안내한다.
- 다른 기기에서 동시에 수정: 마지막 저장이 이긴다. 마지막 저장 시각을 보여 준다.

## 핵심 기능
1. **자연어 → 제약 카드.** 템플릿 12개 중에서 고르고 파라미터를 채운다. 사람이 [적용]해야 반영된다.
   - 기본값 hard
     1. 일일 필요 인원(화면에서는 숫자 하나, 규칙으로는 최소~최대 범위도 가능)
     2. 금지 순서
     3. 최대 연속 근무
     4. 최대 연속 나이트
     5. 최소 오프 일수 (기간당)
     6. N-OFF
     7. 숙련도 믹스
     8. 휴가 (항상 hard)
     9. 고정 배정 (항상 hard)
   - 기본값 soft
     10. 희망 / 기피 근무
     11. 나이트 공정성
     12. 주말·공휴일 공정성
2. **CP-SAT 근무표 생성.**
   - 기간은 병동의 기간 단위를 따른다(7·14·28일 또는 달력 월 28~31일).
   - 주말은 토·일과 체크한 공휴일이다.
   - 나이트 전담은 N/O만 배정하고 나이트 공정성 계산에서 제외한다.
   - 지난 기간 이월 근무를 반영한다.
3. **해가 없을 때 원인 설명.** 충돌하는 제약을 찾아 설명하고, 재풀이로 검증한 완화 제안만 보여준다.
4. **최소 변경 재스케줄.** 수동 고정과 운영 중 변경을 반영하고, 변경 칸을 표시한다.
5. **개인별 통계와 CSV.**
   - 통계: D/E/N/O 개수, 주말·공휴일 근무 수, 최대 연속 근무, 희망 반영률, 평균 대비 편차, 최근 4주 누적 나이트·주말
   - CSV: 행은 간호사, 열은 이름·연차·기간의 날짜·합계. 첫 행에 요일, 하단에 날짜별 D/E/N 합계. UTF-8 BOM.
6. **기간 연속성.**
   - 지난 확정본의 마지막 며칠을 다음 기간의 이월 근무로 자동으로 채운다.
   - 최근 4주의 나이트·주말 근무를 나이트 공정성과 주말·공휴일 공정성에 반영한다.
   - 운영 중인 기간의 지난 날짜는 자동으로 고정한다.
7. **저장과 로그인.**
   - 로그인하지 않아도 확정, 다음 기간, 운영 중 변경까지 모든 기능을 쓸 수 있다(브라우저에 저장).
   - 로그인은 요구하지 않고 권한다: 상단 바의 [Google로 로그인], 게스트가 확정한 직후의 저장 안내 배너. 로그인하면 게스트 데이터를 내 병동으로 옮긴다.
   - 로그인 후에는 서버에 저장된다. 사용자 1명당 병동 1개다.
   - 내 병동 데이터를 직접 삭제할 수 있다.
8. **LLM 번역 정확도 eval.** 수간호사 말투 40개 내외의 데이터셋으로 측정한다.
9. **랜딩페이지(`/`).** 수간호사가 읽는다고 보고 쓴다. 기술 설명은 맨 아래 한 섹션으로 줄인다. 정적 페이지이고 API를 호출하지 않는다.
   - 첫 화면: 좌측 텍스트(한 줄 가치 제안 + [샘플로 체험하기] → `/demo`, [내 병동으로 시작하기] → `/app?start=new`, GitHub Text 링크), 우측 실제 제품 화면 조각(규칙 카드, 근무표 일부). 중앙 정렬 히어로와 장식 이미지는 쓰지 않는다(UI_GUIDE)
     - 가치 제안은 근무표 주기에 묶지 않는다("한 달" 대신 "근무표"). 예: "말로 설명한 규칙으로 근무표를 짭니다"
     - 화면 조각의 열 이름과 용어는 앱과 같은 화면 문구를 쓴다(UI_GUIDE "문구")
   - 문제: 수간호사 페인 포인트
   - 동작 방식: 말로 규칙 입력 → 근무표 만들기 → 막히면 이유와 해결책 → 다음 근무표로 이어짐. LLM·CP-SAT·템플릿·hard/soft 같은 말을 쓰지 않는다
   - 데모 GIF: 배포 체크포인트에서 녹화해 넣는다. 그전까지는 자리표시
   - 만든 방식(맨 아래, 짧게): LLM은 말을 규칙 카드로 바꾸고 설명만 하며, 근무 배정은 CP-SAT 솔버가 계산한다는 것과 번역 정확도 eval 결과 한 줄. 상세 표와 검증 장치 설명은 GitHub README로 보낸다
   - GitHub 링크, 개인정보처리방침 링크

## 데모 저니 (최종 수용 기준)
1. 랜딩에서 [내 병동으로 시작하기]를 누르고, 15명 명단을 입력한 뒤 공휴일 1일을 체크한다.
2. 규칙 3개를 입력한다(나이트 다음 날 휴무, 나이트 3연속 상한, 조마다 3년차 이상 1명).
3. 요청 2개를 입력한다(휴가는 hard, 주말 오프 희망은 soft).
4. 생성 → 근무표, 요약, 통계.
5. 휴가 2건을 추가하면 해가 없다고 나오고, 설명과 검증된 제안이 뜬다. 수락하면 해결된다.
6. 칸을 🔒 고정한 뒤 재풀이한다.
7. 확정하고 CSV를 받는다.
8. 병가를 입력하면 최소 변경으로 재스케줄된다.
9. [다음 근무표 만들기]를 누르면 날짜 범위와 이월 근무가 자동으로 채워지고, 생성 결과에 누적 부담 근거가 보인다.
