# PRD: 매장 직원 근무표 (LLM + CP-SAT)

## 목표
스케줄 매니저가 직원별 가능 시간을 링크로 받고, 말로 설명한 매장 조건으로 근무표를 만들고, 막히는 이유와 변경 영향을 설명받게 한다. 매주 또는 매달 반복해서 쓸 수 있어야 한다.
- 판매용 제품이 아니라 LLM 활용 빌드 역량을 보여주는 포트폴리오 프로토타입이다.
- 다만 데모에서 끝나지 않고 실사용자가 기간을 넘어 반복해서 쓸 수 있는 수준을 목표로 한다. 저장, 로그인, 직원 링크, 기간 간 이월을 포함한다.
- 계산은 CP-SAT 솔버가 하고, LLM은 매니저의 말을 최적화 문제(규칙 식)로 세우는 모델러이자 막힌 이유를 설명하는 해설자를 맡는다(ADR-019).
- 매장 조건을 시스템이 강제하지 않는다. 필요 인원, 근무 형태, 규칙 모두 말로 정하고 바꿀 수 있다.

## 사용자
- **주 사용자: 스케줄 매니저 1명, 매장 1개.**
  - 예: 카페 1개 매장, 파트타임 포함 직원 12명, 오픈·미들·마감
  - 매장마다 근무표 주기가 다르다. 1주 단위가 기본이고, 2주·4주·한 달 단위로 짜는 매장도 있다.
  - 지금은 메신저로 가능 시간을 모으고, 엑셀과 머릿속 규칙으로 짠다.
  - Google로 로그인해서 쓴다. 매니저 본인도 근무에 들어가면 명단에 넣고, 아니면 넣지 않는다.
- **입력 사용자: 직원.** 매니저가 공유한 공용 링크를 PC 웹 브라우저로 열어, 로그인 없이 자기 이름을 고르고 가능 시간을 입력한다.
- **보조 사용자: 포트폴리오 방문자.** 로그인하지 않고 랜딩의 데모 영상(실제 화면 녹화)을 본다.

| 페인 포인트 | 해결 기능 |
|---|---|
| 직원마다 가능 시간을 메신저로 받아 옮겨 적는다 | 개별 링크와 드래그 입력, 자동 반영 |
| 규칙이 머릿속에만 있다 | 자연어 → 규칙 카드 |
| 가능 시간과 조건이 다 안 맞는데 어디서 막히는지 모른다 | 충돌 설명과, 재풀이로 검증된 완화 제안 |
| 확정 후 병가가 생기면 전체를 다시 짠다 | 최소 변경 재스케줄 |
| "왜 나만 주말이 많아요?"에 근거를 대기 어렵다 | 개인별 통계와 누적 부담 |
| 매번 명단, 규칙, 지난 기간 마지막 근무를 다시 옮겨 적는다 | 저장된 매장과 자동 이월 |
| 지난번에 마감을 많이 한 사람을 이번에 배려하기 어렵다 | 최근 4주 누적 부담을 공정성에 반영 |

## 데이터 층
수명이 다른 세 층으로 나눈다.

| 층 | 내용 | 수명 |
|---|---|---|
| **매장** | 근무 형태(근무 코드·시간), 명단(고정 id, 활성/비활성, 직급), 매장 조건(필요 인원 등 기본 규칙 포함), 기간 단위 | 계속 유지되고 가끔 수정 |
| **기간** | 날짜 범위, 공휴일, 직원별 가능 시간, 이번 근무표 요청, 근무표, 상태(초안/확정), 확정본 버전 | 기간마다 새로 만든다 |
| **이력** | 지난 기간의 확정본 | 쌓인다. 다음 기간의 이월과 누적 부담에 쓴다 |

- **기간 단위**: 매장마다 하나로 고정한다(1주 / 2주 / 4주 / 달력 월). 기본값은 1주다. 첫 기간은 아무 날에서 시작할 수 있고(달력 월은 1~28일, 그날부터 다음 달 같은 날 전날까지), 이후 기간은 직전 기간에 이어진다. 다음 기간 시작일은 뒤로만 미룰 수 있다(ADR-018).
- **근무 형태**: 근무 코드(이름, 시작·끝 시각, 실근무 시간, 세는 근무조)를 매장이 정한다. 기본값은 A 오픈 09:00~15:00, M 미들 12:00~18:00, C 마감 17:00~23:00, 각 실근무 6시간 + O(휴무)다. 실근무 시간은 쉬는 시간 때문에 시각 차이와 다를 수 있다. 솔버는 이 코드 중에서만 배정하고 임의의 시간을 만들지 않는다. 하루 두 근무는 복합 코드(예: AC 더블)로 정의한다. 한 번 쓰인 코드는 지우지 않고 끈다.
- **직급**: 직원마다 선택 입력하는 자유 직급(리더, 신입, 주방 등)을 둔다. 추천 직급은 두지 않는다. 규칙의 대상을 고를 때 쓴다.
- **직원 id**: 한 번 정하면 다시 매기지 않는다. 명단을 고치거나 순서를 바꿔도 요청과 고정 배정이 다른 사람에게 옮겨 가지 않는다.
- **기간 분리**: 기간마다 데이터가 분리된다. 다른 기간의 날짜, 고정 배정, 확정본이 섞이지 않는다.

## 화면
- **랜딩**(`/`): 소개 페이지. [데모 영상]는 영상 대화상자를 열고(J7), [내 매장으로 시작하기]는 앱으로 간다.
- **직원 가능 시간 입력**(`/a/{토큰}`): 직원이 링크로 여는 화면. 로그인이 없다(J2).
- **앱**(`/app`, 로그인 필요)
  - 로그인 화면: 로그인하지 않았을 때 보인다. [Google로 로그인]이 있다.
  - 매장 준비: 매장이 없을 때 한 번 보인다. 매장 이름, 근무표 주기, 직원 명단.
  - 매장 홈([근무표] 탭): 운영 중인 기간, 다음 기간 상태, 최근 기간 목록
  - 매장 설정: 명단, 근무 형태, 매장 조건, 기간 단위. 언제든 고칠 때 쓴다
  - 근무표 작성: 확정 전 기간. ① 가능 시간 → ② 매장 조건 → ③ 근무표. 확정은 ③의 끝 버튼이다
  - 확정 근무표: 확정한 기간. 운영 중 변경, 다시 확정, CSV. 끝난 기간은 보기 전용
  - 기간을 열면 상태로 화면이 정해진다(초안 → 근무표 작성, 확정 → 확정 근무표).
- 화면 배치의 세부는 UI_GUIDE에서 정한다.
- 이 문서의 기간, 이월, 초안, 비활성, hard/soft는 데이터 용어다. 화면에는 UI_GUIDE "문구" 표의 말(근무표, 지난 근무 마지막 며칠, 작성 중, 제외, 반드시/가능하면)로 쓴다.

## 사용자 저니
- 기준 인물: 카페 매니저, 직원 12명, 오픈·미들·마감, 1주 단위
- 변형 인물: 음식점 매니저, 직원 20명, 2주 단위
- 사용 사이클: 다음 기간이 시작하기 며칠 전에 가능 시간을 모으고, 시작 전에 확정·공지한다. 운영 중에는 수시로 수정한다.

### J0. 발견과 첫 진입 (방문자, 매니저)
- 생각: "우리 매장 조건으로도 짤 수 있나? 매번 다시 입력해야 하나?"
- 흐름: 랜딩 → [데모 영상](J7) 또는 [내 매장으로 시작하기] → 앱
  - 로그인하지 않았으면 로그인 화면을 보여 준다. Google 로그인 뒤 매장이 없으면 매장 준비(J1), 있으면 매장 홈이나 작성 중인 근무표로 간다.
- 끝: 데모 영상 또는 매장 준비

### J1. 매장 준비 (처음 한 번)
- 생각: "우리 직원 명단만 넣고 바로 시작하고 싶다."
- 매장 이름, 근무표 주기(기본 1주), 명단을 넣는다. 활성 직원이 1명 이상이어야 [첫 근무표 시작하기]를 누를 수 있다.
  - 명단 표에 이름과 직급(선택)을 한 명씩 직접 적는다. 표 맨 아래 입력 줄에서 Enter나 [추가]로 더한다. 파일 올리기와 붙여넣기는 없다.
  - 이름 입력란에 "이니셜을 써도 됩니다"를 안내한다.
- 첫 근무표의 시작일을 고르면 근무표 작성 ① 가능 시간으로 간다.
- 고친 내용은 다음에 생성하는 기간부터 적용된다. 이미 확정된 기간은 바뀌지 않는다.

### J2. 근무표 작성 (반복 사용의 핵심)
근무표마다 같은 세 단계다. 스테퍼로 오가고, 확정은 ③의 끝 버튼이다.

**① 가능 시간**
- 맨 위에 이 근무표의 날짜 범위, 공휴일, 지난 근무 요약. [바꾸기]로 펼친다.
  - 첫 근무표는 시작일을 고른다(기본값 오늘 이후 첫 월요일 또는 1일). 다음 근무표는 직전 근무표 다음 날부터 이어지고, 시작일을 뒤로만 미룰 수 있다.
- 근무표마다 공용 링크 하나와 [링크 복사] 버튼이 있다. 매니저가 복사해서 카카오톡 단체 대화방 등에 직접 공유한다. 서비스가 문자나 이메일을 보내지 않는다.
- 제출 현황("8명 중 5명 제출", 미제출자 이름)과 [새로고침]을 보여 준다.
- 같은 화면에서 직원이 제출한 가능 시간을 한 번에 본다. 날짜별 근무조 가능 인원과 직원별 읽기 전용 캘린더를 보여 주고, 매니저가 고칠 수는 없다.
- 직원 화면(`/a/{토큰}`)
  - 매장 이름, 근무표 날짜 범위, 명단이 보인다. 자기 이름을 고르면 캘린더로 간다. 이미 제출한 이름을 고르면 한 번 더 묻는다.
  - 다른 직원의 이름과 제출 여부는 보이지만, 칠한 내용은 그 이름을 골라야 보인다. 본인 확인은 하지 않는다(ADR-021).
  - 날짜를 열로, 06:00~24:00을 30분 칸으로 둔 캘린더에서 가능한 시간대를 드래그해 칠한다. 칠한 칸에서 시작한 드래그는 지운다. 2주 이상이면 주를 넘겨 입력한다.
  - [제출]하면 저장된다. 같은 링크로 다시 열어 이름을 고르고 고칠 수 있고, 매니저가 근무표를 확정하면 잠긴다.
- 직원은 모두 제출한다고 가정한다. 미제출 경고, 독촉, 대리 입력을 두지 않는다.
- 끝: [다음] → ② 매장 조건

**② 매장 조건**
- 근무 형태, 필요 인원, 그 밖의 규칙을 한 입력창에 말로 적는다(예: "평일 오픈 2명, 주말은 3명", "12시부터 15시까지는 최소 3명", "마감 다음 날 오픈은 안 되게"). 맨 위에 근무조·필요 인원 요약표, 아래에 규칙 카드를 둔다.
  - 근무 형태 변경 카드, 필요 인원 카드(`기본` 배지), 규칙 카드가 생기고, [적용]해야 반영된다.
  - 시간대 필요 인원은 그 시간을 덮는 근무조를 세는 규칙으로 세운다(오픈 + 미들 ≥ 3). 카드 문장과 예시로 사람이 확인한다.
  - 숫자로 넣고 싶으면 접힌 "숫자로 입력하기"를 연다. 근무조(복합 코드 제외)·요일 종류마다 최소·최대를 받고, 같으면 정확히 그 인원이다.
  - 카드에는 규칙을 사람이 읽는 문장(식에서 결정적으로 만든다, 조정 가능한 값은 밑줄), 원문, 예시 판정(이런 근무면 위반이에요, 최대 3개), hard/soft 토글, soft일 때 중요도(높음·보통·낮음), 적용/수정/삭제 버튼이 있다.
  - "피크 근무 P 11시~14시 추가"처럼 근무 형태를 바꾸는 말은 설정 변경 카드가 된다. 새 코드를 쓰는 규칙 카드는 그 설정 카드에 딸려 함께 적용된다.
  - 입력이 모호하면 되묻고, 지원하지 않는 규칙이면 그렇다고 안내한다.
- 한 번 적용한 조건은 저장되어 다음 근무표에도 그대로 쓴다. 다음부터는 확인만 하고 넘어가면 된다.
- 필수 입력이 아니다. [다음]은 항상 누를 수 있고, 필요 인원이 없으면 "필요 인원 없이 만들면 인원을 맞추지 않아요"를 안내한다. 적용하지 않은 카드가 남아 있으면 빠진다고 안내한다.
- 근무조 합계로 미리 막지 않는다. 만들 수 없으면 ③에서 솔버가 해 없음과 이유를 알려 준다.
- 규칙 카드 아래에서 이번 근무표에만 적용할 예외를 말로 적을 수 있다(선택, 평소에는 접혀 있다, 요청 카드). 예: "이영희 15일 휴가", "김철수는 이번 주 마감 빼 줘". 가능 시간에 이미 있는 내용은 다시 적지 않는다. ②는 만들기 전에 정하는 조건, ③은 결과와 결과 위의 손질을 맡는다.

**③ 근무표**
- 생성: 근무표, 요약(희망 반영 수, soft 위반)을 보여 준다. 개인별 통계는 [개인별 통계 보기]를 누르면 펼친다. 직원은 자기 가능 시간이 근무조 시각을 완전히 덮는 칸에만 배정된다.
- 해가 없을 때: 충돌 설명과, 재풀이로 검증된 완화 제안을 보여 준다.
  - 제안을 [수락]하면 재풀이한다. 가능 시간은 완화하지 않는다. 직원이 정한 시간이므로 제안은 매장 조건만 바꾼다.
  - 제안이 없거나 LLM이 실패하면 매장 조건에 [이번 근무표에서만 끄기]를 쓴다.
- 조정: 칸을 수정하고 🔒 고정한 뒤 재풀이한다. 칸 고정은 가능 시간보다 우선한다(매니저가 직원과 합의한 경우).
- [확정]하면 확정 근무표 화면으로 옮겨 간다. 직원 링크는 잠긴다.

**다음 근무표**
- 생각: "지난번 설정 그대로, 가능 시간만 새로 받고 싶다. 지난번에 마감을 많이 한 사람은 이번에 덜 하게."
- 매장 홈 [다음 근무표 만들기] → ① 가능 시간. 날짜 범위, 이월, 명단, 매장 조건이 이어지고, 링크는 근무표마다 새로 만든다.
- 명단 점검: 지난 확정 기간 이후 추가·비활성화된 직원을 요약에 보여 준다.
- 결과에 누적 부담 근거를 보여 준다. 예: "지난 4주 마감 6회 → 이번 기간 1회"
- 끝: 다음 기간 확정, 이력 1개 추가

### J4. 운영 중 변경 (수시)
- 생각: "확정 공지는 이미 나갔다. 바꾸는 칸은 최소로 하고, 이미 지난 날은 건드리면 안 된다."
- 흐름
  1. 매장 홈 → 운영 중 카드의 [변경 입력] → 확정 근무표 화면(변경 입력 바에 포커스)
  2. "최지훈 이번 주 병가"를 입력하고 카드를 [적용]한다.
  3. 최소 변경으로 재스케줄하고, 변경된 칸을 하이라이트한다.
  4. [다시 확정]. 다시 확정하기 전에는 [변경 취소]로 마지막 확정본(배정과 요청)으로 되돌릴 수 있다.
- 규칙
  - 오늘 이전 날짜는 자동으로 고정되어 바뀌지 않는다.
  - 확정한 뒤에는 근무표 작성으로 돌아가지 않는다. 시작 전에 확정한 기간도 늦게 온 요청을 변경 입력으로 넣는다.
  - 끝난 기간(오늘이 기간 뒤)은 보기 전용이다. 변경 입력을 두지 않는다.
  - [다시 확정]할 때마다 확정본 버전(시각, 바뀐 칸)을 남긴다. 버전을 비교하거나 복원하는 화면은 두지 않는다.
- 연쇄 영향: 이 기간이 바뀌어 다음 기간의 이월이 달라지면 "지난 근무표가 바뀌어 이어지는 근무가 달라졌어요" 배너를 띄운다. 다음 기간이 초안이든 확정이든 같다. 이월은 다음에 생성할 때 다시 계산한다.

### J5. 명단 변동 (입사, 퇴사, 장기 휴직)
- 생각: "퇴사한 사람이 지난 근무표에서 사라지면 안 된다."
- 규칙
  - 직원은 삭제하지 않고 비활성으로 둔다.
  - 비활성 직원은 이력과 통계에는 남고, 새 기간 생성에서는 빠진다.
  - id는 다시 매기지 않는다.

### J6. 공용 PC와 데이터 삭제
- 로그아웃하면 이 브라우저에 남은 매장 데이터를 지운다.
- [내 매장 데이터 삭제]는 서버의 매장 데이터를 모두 지운다(확인 2단계). Google 계정 연결 자체는 남는다.

### J7. 데모 영상 (방문자)
- 랜딩의 [데모 영상]가 대화상자로 영상(`public/demo.mp4`, 2분 안쪽)을 연다. 페이지를 옮기지 않고, 저장하지 않고, API를 부르지 않는다(ADR-022).
- 보여 주는 것: 실제 앱을 녹화한 한 흐름(한강 다이닝, 직원 20명). 랜딩 → 매장 준비(명단과 직급) → 근무 형태 → ① 직원 링크 → 직원 화면에서 가능 시간 칠하고 제출 → 제출 현황 → ② 매장 조건 두 문장 → 카드 적용 → ③ 근무표 만들기 → 근무표 없음과 이유 → 검증된 제안 [수락] → 근무표 → 확정.
- 영상은 `npm run record:dining`(`scripts/record-dining.ts`)이 테스트 계정의 빈 매장에서 시작해 Playwright로 녹화해 만든다(시나리오는 `docs/DEMO_SCENARIO.md`). 화면이 바뀌면 다시 만든다.
- 끝: Esc나 [닫기] → 랜딩 그대로 → [내 매장으로 시작하기] → 앱(J0)

### J8. 실패와 예외
- LLM 장애: 규칙 카드를 직접 수정하거나 [이번 근무표에서만 끄기]로 진행할 수 있다.
- 직원 링크 오류: 토큰이 틀리면 "링크를 확인해 주세요", 확정 뒤에는 "이미 확정된 근무표예요"를 보여 주고 입력을 막는다.
- 저장 실패(네트워크): 브라우저에 보관하고 다시 시도한다고 안내한다.
- 다른 기기에서 동시에 수정: 마지막 저장이 이긴다. 마지막 저장 시각을 보여 준다.

## 핵심 기능
1. **자연어 → 규칙 카드.** LLM이 말을 규칙 식으로 세운다(ADR-019). 사람이 [적용]해야 반영된다.
   - **식**: 범위(기간 / 날마다 / 사람마다 / 사람·날마다 / 사람·주마다 / 사람·연속 n일마다) + 본문이다.
     - 본문은 세기(고른 사람 × 날짜 × 근무의 개수나 근무 시간), 비교(이상·이하·같음, 숫자나 다른 세기와), 그리고/또는, 만약 ~면, 날짜 이동(다음 날, 앞 2일 등)의 조합이다.
     - 내장 함수 고르게: 고른 사람 사이의 개수·시간 차이를 줄인다. 최근 4주 근무를 더해서 센다.
     - 예: 필요 인원, 시간대 필요 인원, 직급별 배치, 최소 휴무, 휴가, 희망·기피, 주 근무 시간 상한·하한, 금지 순서, 연속 근무 길이, "신입이 마감이면 리더도 마감에 1명"(조건부), "김OO와 이OO는 같은 날 마감 금지"(짝), "오픈의 리더 수가 신입 수 이상"(세기끼리 비교)
     - 노동법을 스스로 판단하지 않는다. 주휴, 주 15시간 같은 조건도 사용자가 말한 규칙만 지킨다.
   - 대상 고르기: 사람(명단·직급), 날짜(평일·주말·공휴일, 요일, 특정일), 근무(코드 집합 또는 "휴무 말고 모두" 같은 제외 집합)
   - 식 안의 숫자는 이름이 있는 **조정 가능한 값**이다(예: 최대 연속 근무 = 5). 카드 [수정]과 완화 제안은 이 값을 바꾼다.
   - **의미 확인**: 카드 문장은 식에서 결정적으로 만들고, 서버가 샘플 근무표에서 찾은 위반 사례를 예시로 보여 준다.
   - 칸 고정(수동 고정, 지난 날짜 잠금)은 규칙이 아니라 항상 지키는 데이터다.
   - 기본값: 규칙은 반드시, 고르게와 희망·기피는 가능하면. 휴가 카드는 항상 반드시다.
   - 가능하면 규칙은 중요도 높음·보통·낮음을 가진다. 기본값은 보통, 고르게는 낮음이다.
   - 근무 형태(근무 코드 추가·수정)도 말로 바꿀 수 있다. 설정 변경 카드로 제안되고 [적용]해야 반영된다.
   - **기본 규칙**: 필요 인원은 `기본` 배지 카드다. 다른 규칙처럼 말로 고치거나 끌 수 있다.
2. **CP-SAT 근무표 생성.**
   - 가능 시간은 코드가 근무조 시각과 비교해 반드시 지키는 규칙으로 바꾼다. LLM을 거치지 않는다.
   - 기간은 매장의 기간 단위를 따른다(7·14·28일 또는 달력 월 28~31일).
   - 칸마다 근무 코드 하나다. 하루 두 근무는 복합 코드로 배정한다.
   - 주말은 토·일과 체크한 공휴일이다.
   - 지난 기간 이월 근무를 반영한다.
3. **해가 없을 때 원인 설명.** 충돌하는 규칙을 찾아 설명하고, 재풀이로 검증한 완화 제안만 보여준다. 완화는 조정 가능한 값 바꾸기, 끄기, 반드시 → 가능하면만 한다.
4. **최소 변경 재스케줄.** 수동 고정과 운영 중 변경을 반영하고, 변경 칸을 표시한다.
5. **개인별 통계와 CSV.**
   - 통계: 근무 코드별 개수, 근무 시간, 주말·공휴일 근무 수, 최대 연속 근무, 희망 반영률, 평균 대비 편차, 최근 4주 누적 마감·주말
   - CSV: 행은 직원, 열은 이름·기간의 날짜·합계. 첫 행에 요일, 하단에 날짜별 근무조 합계. UTF-8 BOM.
6. **기간 연속성.**
   - 지난 확정본의 마지막 며칠을 다음 기간의 이월 근무로 자동으로 채운다.
   - 최근 4주의 확정 근무를 고르게 규칙에 반영한다.
   - 운영 중인 기간의 지난 날짜는 자동으로 고정한다.
7. **저장과 로그인.**
   - 앱은 Google 로그인이 필요하다. 사용자 1명당 매장 1개이고 서버에 저장한다. 게스트 모드는 없다.
   - 직원 링크는 추측할 수 없는 근무표당 공용 토큰이고, 그 근무표의 명단과 직원 입력만 읽고 쓸 수 있다.
   - 내 매장 데이터를 직접 삭제할 수 있다. 가능 시간도 함께 지워진다.

8. **LLM 번역 정확도 eval.** 매니저 말투 100개 내외의 데이터셋으로 측정한다. 같은 규칙의 다른 식 모양을 맞게 보도록, 무작위 근무표에서 위반이 같은지로 판정한다.
9. **랜딩페이지(`/`).** 매니저가 읽는다고 보고 쓰되, 30초 안에 판단하는 포트폴리오 방문자도 같은 화면에서 제품의 핵심 순간과 완성도를 볼 수 있어야 한다. 기술 설명은 아래쪽 한 섹션으로 줄인다. 정적 페이지이고 API를 호출하지 않는다.
   - 상단 바: 워드마크, GitHub
   - 첫 화면: 좌측 텍스트(한 줄 가치 제안 + [데모 영상] → 영상 대화상자, [내 매장으로 시작하기] → `/app`), 우측 히어로 시퀀스(실제 컴포넌트로 "말 한 줄 → 규칙 카드 → 근무표"가 한 번 재생되고 [다시 보기]). 중앙 정렬 히어로와 장식 이미지는 쓰지 않는다(UI_GUIDE)
     - 가치 제안은 근무표 주기에 묶지 않는다("한 달" 대신 "근무표"). 예: "복잡한 근무표, 이제 스케줄링 AI에게 맡기세요"
     - 화면 조각의 열 이름과 용어는 앱과 같은 화면 문구를 쓴다(UI_GUIDE "문구")
   - 문제: 매니저 페인 포인트를 "지금 ↔ 스케줄링 AI에서는" 전/후 쌍 3개(가능 시간 모으기, 머릿속 규칙, 막힘)로 보여 주고, 나머지 3개(통계 근거, 운영 중 변경, 이어받기)는 짧게 둔다
   - 동작 방식: 가능 시간 링크 → 말로 매장 조건 → 근무표 만들기와 막힌 이유 → 확정과 최소 변경. 단계마다 실제 화면 조각을 붙인다. LLM·CP-SAT·템플릿·hard/soft 같은 말을 쓰지 않는다
   - 데모 GIF 섹션은 두지 않는다. 히어로 시퀀스가 대신하고, 전체 흐름은 [데모 영상]의 영상이 보여 준다
   - 만든 방식(짧게): 말은 LLM이, 계산은 CP-SAT 솔버가, 검증은 재풀이로 한다는 것과 번역 정확도 eval 결과 한 줄(수치가 없으면 자리표시). 상세 표와 검증 장치 설명은 GitHub README에서 링크한 문서(`docs/`, `eval/results.md`)로 보낸다
   - CTA 띠: "직원 명단만 넣으면 첫 근무표를 시작할 수 있어요" + [내 매장으로 시작하기] [데모 영상]
   - 푸터: GitHub 링크, 개인정보처리방침 링크

## MVP 제외 사항
- 결제, 공유 링크
- 하루 세 근무 이상, 근무 시각 겹침을 솔버가 직접 계산하는 것, 근무조에 없는 자유 시간대 배정, 근무 코드보다 잘게 쪼갠 시간(교육·회의)
- 노동법 자동 판단, 인건비 계산
- 다중 매장, 매장 공유와 다중 사용자, 직원 계정과 직원용 근무표 열람, 링크 자동 발송(문자·이메일), 미제출 처리(경고·독촉·대리 입력)
- 근무 교환
- Google 외 로그인(매직 링크 등), 게스트 모드, 인증 계정 자체 삭제, 다중 기기 실시간 동기화
- 확정본 버전 비교·복원 화면
- API 사용량 제한
- 인쇄용 뷰, JSON 내보내기/불러오기
- LLM 요약 문장, 공정성 Q&A, 숫자 가중치 UI(중요도 3단계만 둔다)
- 모바일(직원 입력 화면 포함), 자정을 넘기는 근무조, 다국어, 스트리밍
- 자체 솔버, 모델 비교 eval

## 디자인
- 제품 이름은 **스케줄링 AI**다. 화면 문구, 워드마크, 브라우저 탭 제목에 쓴다. 코드 식별자와 저장소 이름은 바꾸지 않는다.
- `docs/UI_GUIDE.md`를 따른다. 결정 기록과 시안 링크는 `docs/DESIGN_BRIEF.md`에 있다.

## 데모 저니 (최종 수용 기준)
1. 랜딩에서 [내 매장으로 시작하기]를 누르고 Google로 로그인한 뒤, 12명 명단을 입력한다.
2. 공용 링크를 복사하고, 링크를 열어 이름을 고른 뒤 캘린더를 드래그해 가능 시간을 제출한다.
3. 매장 조건을 입력한다(필요 인원, 마감 다음 날 오픈 금지, 최대 연속 근무 5일, 오픈에 리더 1명).
4. 생성 → 근무표, 요약, 통계. 모든 배정이 가능 시간 안에 있다.
5. ②에서 예외 휴가를 더해 해가 없다고 나오면, 설명과 검증된 제안이 뜬다. 수락하면 해결된다.
6. 칸을 🔒 고정한 뒤 재풀이한다.
7. 확정하고 CSV를 받는다. 직원 링크가 잠긴다.
8. 병가를 입력하면 최소 변경으로 재스케줄된다.
9. [다음 근무표 만들기]를 누르면 날짜 범위와 이월 근무가 자동으로 채워지고, 생성 결과에 누적 부담 근거가 보인다.
