# 브라우저 테스트 시나리오

PRD의 데모 저니(최종 수용 기준)를 브라우저에서 확인하는 유저 케이스다.
이 문서를 기준으로 실행 스크립트를 만든다. 그래서 각 단계에 **대상(접근성 역할과 이름)**, **값**, **검증**을 적었다.
범위는 **게스트 모드**까지다(ADR-014). 로그인과 Supabase 저장은 자동화하지 않는다.
범위에서 뺀 것: CSV 파일 올리기, CSV 다운로드, 로그인.

## 실행 환경
- 실행: `npm run test:e2e` (Playwright, `e2e/`). 서버가 떠 있지 않으면 Playwright가 Next와 FastAPI를 띄운다. 처음 한 번은 `npx playwright install chromium`이 필요하다.
- 서버: `npm run dev` (Next :3000 + FastAPI :8000). 기준 URL은 `http://localhost:3000`
- `.env.local`에 `ANTHROPIC_API_KEY`가 있어야 한다. 규칙·요청 해석, 충돌 설명, 운영 중 변경이 실제 API를 부른다(LLM을 mock하지 않는다, ADR-013).
- 저장소: localStorage 키 `nurse-scheduler`. 시나리오 시작 전에 지우면 깨끗한 상태가 된다(Playwright는 새 브라우저 컨텍스트라 비어 있다).
- **시간 고정**: 실행일과 무관하게 같은 날짜가 나오도록 브라우저 시계를 고정한다.
  - 기본: `page.clock.setFixedTime(new Date("2026-10-28T09:00:00+09:00"))` (수요일). 첫 페이지 이동 전에 건다.
  - 운영 중 변경(S11)부터: `page.clock.setFixedTime(new Date("2026-11-09T09:00:00+09:00"))` (월요일)로 옮기고 새로고침한다.
  - translate 요청의 `today`도 클라이언트 시계로 보내므로 함께 고정된다.
- 대기 시간 상한
  - LLM 해석(`/api/py/translate`): 30초. 버튼이 "해석 중…"에서 "해석"으로 돌아올 때까지 기다린다.
  - 생성(`/api/py/solve`): 15초. 버튼이 "푸는 중…"에서 "생성"으로 돌아올 때까지 기다린다.
  - 충돌 설명(`/api/py/explain`): 40초. "원인을 분석하는 중…"이 사라질 때까지 기다린다.
- 모든 시나리오 공통 검증
  - 콘솔에 error 레벨 메시지가 없다.
  - `/api/*` 응답이 모두 2xx다.
  - 오류 알림(`role=alert`, [다시 시도] 포함)이 뜨지 않는다.
- 해석 결과는 LLM에 따라 조금씩 다를 수 있다. 그래서 카드 문구 전체를 맞추지 않고 **카드 제목(템플릿 이름)과 파라미터 요약의 핵심 값**만 검증한다.

## 대상 표기
- `button "생성"`: 역할이 button이고 접근성 이름이 "생성"인 요소
- `textbox "병동 규칙 입력"`: aria-label이 "병동 규칙 입력"인 입력칸
- `text "해 있음"`: 화면에 보이는 텍스트
- 근무표 칸: `button "{이름} {M}월 {D}일 {코드}"` (예: `button "김철수 11월 10일 D"`). 코드는 D/E/N/O 중 하나다. 월은 날짜마다 계산한다.
- 이월 근무 칸: `[aria-label="{이름} {M}/{D} {코드}"]` (`<div>`, 편집하지 않음)

## 시나리오 진행 순서
S1, S2는 각각 독립이다. S3부터 S13은 앞 시나리오의 상태를 이어받는 **하나의 연속 흐름**이다.

```
S1 ─ 독립
S2 ─ 독립
S3 → S4 → S5 → S6 → S7 → S8 → S9 → S10 → S11 → S12 → S13
병동 설정      첫 기간(2026-11)                     운영 중   다음 기간  이어서 하기
```

## S4. 병동 설정: 병동 규칙 (데모 저니 2)
**사전 상태**: S3 끝. `tab "병동 규칙"`을 누른다. 입력칸은 `textbox "병동 규칙 입력"`, 제출은 `button "해석"`이다.

### S4-a. 규칙 해석과 적용
아래 입력을 하나씩 넣고 [해석]한다. 해석이 끝날 때마다 카드를 확인한다.

| # | 입력 | 기대 카드 제목 (하나) | 파라미터 요약 핵심 | 토글 |
|---|---|---|---|---|
| R1 | 나이트 다음 날은 무조건 쉬게 | "나이트 후 오프 (N-OFF)" 또는 "금지 순서" | `N 뒤 O 1일`, 또는 `N → D 금지`·`N → E 금지` | hard |
| R2 | 나이트는 3일 넘게 연속으로 하지 않게 | "최대 연속 나이트" | `연속 N ≤ 3일` | hard |
| R3 | 근무조마다 3년차 이상 한 명은 꼭 있어야 해 | "숙련도 믹스" (D/E/N 각각 1장씩일 수 있음) | `3년차 이상 ≥ 1명` | hard |
| R4 | 나이트는 다 같이 공평하게 나눠 줘 | "나이트 공정성" | | soft |

R4는 다음 기간(S12)에서 누적 부담이 공정성에 반영되는지 보려고 넣는다.

각 카드의 공통 검증:
- 원문이 “따옴표”로 보인다.
- 배지가 "적용 대기"이고 `button "삭제"`, `button "적용"`이 있다.
- `group "hard/soft"` 안에서 기대 토글 버튼이 aria-pressed=true다.

이어서 다음을 진행한다.

| # | 동작 | 대상 | 값 |
|---|---|---|---|
| 1 | 확인 | text | "적용하지 않은 카드 N개는 근무표에 반영되지 않아요." (N = 대기 카드 수) |
| 2 | 클릭 | R2 카드의 `button "soft"` | |
| 3 | 확인 | R2 카드의 `button "soft"` | aria-pressed=true |
| 4 | 클릭 | R2 카드의 `button "hard"` | 되돌림 |
| 5 | 클릭 | 모든 대기 카드의 `button "적용"` | |
| 6 | 확인 | 모든 카드 | 배지 "적용됨", 1의 안내 문구 사라짐 |

| # | 입력 | 기대 결과 |
