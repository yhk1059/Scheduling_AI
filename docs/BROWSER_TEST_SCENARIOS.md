# 브라우저 테스트 시나리오

PRD의 데모 저니(최종 수용 기준)를 브라우저에서 확인하는 유저 케이스다.
이 문서를 기준으로 실행 스크립트를 만든다. 그래서 각 단계에 **대상(접근성 역할과 이름)**, **값**, **검증**을 적었다.
범위에서 뺀 것: CSV 파일 올리기, CSV 다운로드.

## 실행 환경
- 실행: `npm run test:e2e` (Playwright, `e2e/`). 서버가 떠 있지 않으면 Playwright가 Next와 FastAPI를 띄운다. 처음 한 번은 `npx playwright install chromium`이 필요하다.
- 서버: `npm run dev` (Next :3000 + FastAPI :8000). 기준 URL은 `http://localhost:3000`
- `.env.local`에 `ANTHROPIC_API_KEY`가 있어야 한다. 규칙·요청 해석, 충돌 설명, 월중 변경이 실제 API를 부른다.
- 저장소: localStorage 키 `nurse-scheduler`. 시나리오 시작 전에 지우면 깨끗한 상태가 된다.
- 대기 시간 상한
  - LLM 해석(`/api/translate`): 30초. 버튼이 "해석 중…"에서 "해석"으로 돌아올 때까지 기다린다.
  - 생성(`/api/solve`): 15초. 버튼이 "푸는 중…"에서 "생성"으로 돌아올 때까지 기다린다.
  - 충돌 설명(`/api/explain`): 40초. "원인을 분석하는 중…"이 사라질 때까지 기다린다.
- 모든 시나리오 공통 검증
  - 콘솔에 error 레벨 메시지가 없다.
  - `/api/*` 응답이 모두 2xx다.
  - 오류 토스트(`role=alert`)가 뜨지 않는다.
- 해석 결과는 LLM에 따라 조금씩 다를 수 있다. 그래서 카드 문구 전체를 맞추지 않고 **카드 제목(템플릿 이름)과 파라미터 요약의 핵심 값**만 검증한다.

## 대상 표기
- `button "생성"`: 역할이 button이고 접근성 이름이 "생성"인 요소
- `textbox "병동 규칙 입력"`: aria-label이 "병동 규칙 입력"인 입력칸
- `text "해 있음"`: 화면에 보이는 텍스트
- 근무표 칸: `button "{이름} 11월 {일}일 {코드}"` (예: `button "김철수 11월 10일 D"`). 코드는 D/E/N/O 중 하나다.

## 시나리오 진행 순서
S1, S2는 각각 독립이다. S3부터 S10은 앞 시나리오의 상태를 이어받는 **하나의 연속 흐름**이다. S11은 S10 뒤에 실행한다.

```
S1 ─ 독립
S2 ─ 독립
S3 → S4 → S5 → S6 → S7 → S8 → S9 → S10 → S11
```

## S4. ② 병동 규칙 (데모 저니 2)
**사전 상태**: S3 끝. 입력칸은 `textbox "병동 규칙 입력"`, 제출은 `button "해석"`이다.

### S4-a. 규칙 3개 해석과 적용
아래 입력을 하나씩 넣고 [해석]한다. 해석이 끝날 때마다 카드를 확인한다.

| # | 입력 | 기대 카드 제목 (하나) | 파라미터 요약 핵심 | 토글 |
|---|---|---|---|---|
| R1 | 나이트 다음 날은 무조건 쉬게 | "나이트 후 오프 (N-OFF)" 또는 "금지 순서" | `N 뒤 O 1일`, 또는 `N → D 금지`·`N → E 금지` | hard |
| R2 | 나이트는 3일 넘게 연속으로 하지 않게 | "최대 연속 나이트" | `연속 N ≤ 3일` | hard |
| R3 | 근무조마다 3년차 이상 한 명은 꼭 있어야 해 | "숙련도 믹스" (D/E/N 각각 1장씩일 수 있음) | `3년차 이상 ≥ 1명` | hard |

각 카드의 공통 검증:
- 원문이 “따옴표”로 보인다.
- 배지가 "적용 대기"이고 `button "삭제"`, `button "적용"`이 있다.
- `group "hard/soft"` 안의 `button "hard"`가 aria-pressed=true다.

이어서 다음을 진행한다.

| # | 동작 | 대상 | 값 |
|---|---|---|---|
| 1 | 확인 | text | "적용하지 않은 카드 N개는 근무표에 반영되지 않아요." (N = 대기 카드 수) |
| 2 | 클릭 | R2 카드의 `button "soft"` | |
| 3 | 확인 | R2 카드의 `button "soft"` | aria-pressed=true |
| 4 | 클릭 | R2 카드의 `button "hard"` | 되돌림 |
| 5 | 클릭 | 모든 대기 카드의 `button "적용"` | |
| 6 | 확인 | 모든 카드 | 배지 "적용됨", 1의 안내 문구 사라짐 |

### S4-b. 적용된 카드 수정
| # | 동작 | 대상 | 값 |
|---|---|---|---|
| 1 | 클릭 | R2 카드의 `button "수정"` | |
| 2 | 입력 | R2 카드의 "일수" 입력칸 | `4` |
| 3 | 클릭 | `button "저장"` | |
| 4 | 확인 | R2 카드 요약 | `연속 N ≤ 4일` |
| 5 | 반복 | 1~3 | 값 `3`으로 되돌림, 요약 `연속 N ≤ 3일` |

### S4-c. 되묻기와 미지원 안내
| # | 입력 | 기대 결과 |
|---|---|---|
| 1 | 주말은 적당히 | 질문 문장과 "내용을 보완해서 다시 입력해 주세요."가 보이고, 카드가 늘지 않는다 |
| 2 | 사이 안 좋은 간호사끼리는 같은 날 근무 안 넣게 | "아직 지원하지 않는 규칙이에요:"로 시작하는 문구가 보이고, 카드가 늘지 않는다 |

LLM이 1을 다른 상태로 판단할 수 있다(예: 공정성 카드 생성). 그때는 실패로 보지 않고 결과를 기록한 뒤, 생긴 카드를 `button "삭제"`로 지운다.

| 10-b | 클릭 | 11/20 휴가 카드 행의 `button "이번 달만 끄기"` | 재풀이 완료까지 대기 |
| 11 | 확인 | 요약 | "해 있음" 배지, 결과 패널 사라짐 |

**설계 근거**
- 2, 3이 적용되면 평일인 11/20에 일반 간호사 5명과 나이트 전담 2명, 모두 7명만 남는다. 평일 최소 인원 합계(D3 + E3 + N2 = 8명)를 채울 수 없으므로 해가 반드시 없다.
- 한 문장이 사람별 휴가 카드 여러 장으로 나뉘어도 정상이다. 생긴 카드는 모두 [적용]한다.

**검증**
- 제안 카드에는 "재풀이 결과 · 해 있음 · 희망 반영 x/y"가 있다.
- 10-a로 해결했다면 S6의 H1~H6이 수락으로 바뀐 규칙을 빼고 그대로 성립한다.
- 어느 분기로 해결했는지 결과에 기록한다.
