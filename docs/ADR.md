# Architecture Decision Records

## 철학
포트폴리오 프로토타입이다. 데모 저니에 필요한 것만 만든다.
- LLM은 잘하는 것(자연어 이해와 설명)에만 쓰고, 계산과 검증은 결정적 코드로 한다.
- 외부 의존성과 인프라를 최소화한다. 작동하는 가장 단순한 구현을 고른다.

---

### ADR-001: 계산은 CP-SAT, LLM은 번역과 설명만
**결정**: 근무표는 OR-Tools CP-SAT가 푼다. LLM은 자연어 → 제약 스펙 번역과 충돌 설명만 한다.
**이유**: LLM은 조합 최적화에서 제약을 자주 어긴다. 솔버는 해가 없음을 증명하고, 충돌 원인을 찾을 수 있다.
**트레이드오프**: 자체 솔버로 알고리즘 역량을 보여줄 기회를 포기한다(MVP 이후 선택 과제).

### ADR-002: LLM은 템플릿 12개 중에서 고르고 파라미터만 채운다
**결정**: 제약 템플릿을 코드로 고정한다. LLM은 tool use로 `type`과 `params`만 출력한다. LLM이 코드를 생성하지 않는다.
**이유**: 출력을 검증할 수 있고, eval로 정확도를 측정할 수 있다.
**트레이드오프**: 템플릿에 없는 규칙은 `unsupported`로 거절한다.

### ADR-003: Pydantic을 단일 기준으로
**결정**: `backend/domain/models.py`에서 tool `input_schema`, 검증, 솔버 입력, `lib/types.gen.ts`를 모두 만든다.
**이유**: 계층마다 스키마가 어긋날 여지를 없앤다.
**트레이드오프**: 타입 생성 스크립트를 하나 유지해야 한다.

### ADR-004: LLM 출력은 검증을 통과한 "제안"으로만 쓴다
**결정**: Pydantic 검증과 참조 무결성 검사를 거치고, 실패하면 최대 2회 재시도한다. 결과는 사람이 [적용]하거나 서버가 재풀이로 검증해야 반영된다. explain이 실패하면 결정적 대체 경로로 간다.
**이유**: 환각이 근무표에 직접 들어가지 않게 한다. 프롬프트 인젝션의 영향도 잘못된 제안 카드에 그친다.
**트레이드오프**: 사용자가 클릭을 한 번 더 해야 한다.

### ADR-005: 백엔드는 무상태, 저장은 클라이언트 localStorage
**결정**: DB 없이 Zustand + persist를 쓴다. 매 요청에 병동, 제약, 이전 해를 통째로 보낸다.
**이유**: 서버리스와 잘 맞고, 재스케줄과 재현이 단순하다. 인프라가 필요 없다.
**트레이드오프**: 공유 링크와 다중 기기 동기화가 안 된다(MVP 이후 Supabase 선택 과제).

### ADR-006: `solver/`와 `llm/`은 서로 import하지 않는다
**결정**: 둘의 조합(제안 검증 등)은 `routes.py`에서만 한다. 별도 서비스 계층은 두지 않는다.
**이유**: 각각 독립적으로 테스트할 수 있다(솔버는 실제로 돌리고, LLM은 mock).
**트레이드오프**: `routes.py`에 오케스트레이션 코드가 모인다.

### ADR-007: Next.js + FastAPI를 Vercel 프로젝트 하나로
**결정**: `api/index.py`는 진입점만 두고, 앱 코드는 `backend/` 패키지에 둔다. `/api/py/*`는 리라이트한다(개발 중에는 uvicorn :8000으로).
**이유**: 배포 대상이 하나라 단순하다. Vercel은 `api/*.py`를 각각 함수로 만들기 때문에 앱 코드를 `api/` 밖에 둔다.
**트레이드오프**: Python 함수 번들 크기에 여유가 작다(아래 측정 참고).
**검증(0-spike, 2026-10-26)**
- `backend/`가 번들에 포함됨. health와 solve-demo 모두 200
- Python 3.12를 `.python-version`으로 인식
- Linux 기준 의존성 약 218MB(ortools 82MB, numpy 57MB, pandas 46MB) / 한도 약 250MB
- 첫 호출 0.72초(네트워크 포함), 4×7 풀이 7~93ms
- **규칙**: Python 의존성을 추가하지 말 것. 한도를 넘기면 백엔드만 Cloud Run으로 분리한다.

### ADR-008: 동기 요청과 솔버 시간 제한
**결정**: 큐, 웹소켓, 스트리밍 없이 요청과 응답만 쓴다. 솔버는 10초, 충돌 분석은 5초, 제안 검증은 3초 × 3으로 제한한다.
**이유**: 15명 × 31일 규모는 수 초 안에 풀린다. 이 정도로 충분하다.
**트레이드오프**: 큰 병동(40명 초과)은 지원하지 않는다.

### ADR-009: LLM 호출 전 이름 가명화
**결정**: 명단의 성명 전체와, 명단에서 유일한 이름(성 제외)을 `N01` 같은 가명으로 치환해서 보낸다. 치환되지 않은 이름이 출력에 남으면 `clarify`로 처리한다.
**이유**: 개인정보를 최소한으로 내보낸다.
**트레이드오프**: 별명이나 오타가 섞인 이름은 되묻기로 처리해야 한다.

### ADR-010: 도메인 범위 결정
**결정**
- **기간**: 달력 월(28~31일)
- **주말**: 토·일과 사용자가 체크한 공휴일. 인원 기준과 공정성 계산에 모두 적용한다.
- **hard/soft**: 템플릿 기본값을 두고, LLM이 표현 강도로 조정하며, 카드에서 토글할 수 있다. 휴가와 고정 배정은 항상 hard다. 가중치는 상수로만 둔다.
- **나이트 전담**: N/O만 배정하고 나이트 공정성 계산에서 제외한다. 나머지 규칙은 똑같이 적용한다.
- **명단**: 수간호사는 넣지 않는다.
- **날짜 해석**: translator에 실제 오늘 날짜와 대상 월을 넣는다. eval은 케이스마다 `today`를 고정한다.

**이유**: 한국 병원의 월 단위 3교대 운영에 맞추면서 범위를 좁힌다.
**트레이드오프**: 4주 단위 운영, 다른 근무 형태, 공휴일 데이터 내장은 지원하지 않는다.

### ADR-011: 모델과 공개 방식
**결정**: 모델은 `claude-sonnet-5-5`로 하고 env `ANTHROPIC_MODEL`로 교체할 수 있게 둔다. 데모는 인증 없이 공개한다. 남용은 Anthropic 콘솔 월 한도, 입력 상한, `max_tokens`로 막는다.
**이유**: 포트폴리오 데모는 접근하기 쉬워야 한다. 서버리스에서 메모리 기반 레이트 리밋은 효과가 없다.
**트레이드오프**: 한도에 걸리면 데모가 503 안내를 띄운다.

### ADR-012: TDD 적용 범위
**결정**: `backend/` 전체와 `lib/`의 순수 함수만 테스트를 먼저 작성한다. UI 컴포넌트와 `lib/api.ts`는 build, lint, 수동 저니로 검증한다. TDD 가드 훅도 이에 맞춰 예외를 둔다.
**이유**: 로직은 테스트로 지키고, UI는 컴포넌트 테스트 비용 대비 효과가 낮다.
**트레이드오프**: UI 회귀는 수동 확인에 의존한다.
