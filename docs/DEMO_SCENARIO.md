# 데모 영상 시나리오 (초안)

서비스를 처음 쓰는 매니저가 빈 매장에서 시작해 근무표를 확정하기까지를 한 번에 보여 주는 영상이다.

- **한 줄 이야기**: 조건을 모두 넣었더니 근무표를 만들 수 없었다. 이유와 검증된 대안을 보고, 대안 하나를 받아들여 근무표를 확정했다.
- **보여 줄 것**: 직원은 로그인 없이 링크로 가능 시간을 낸다 / 규칙은 말로 적으면 카드가 된다 / 솔버가 공정한 근무표를 찾거나 불가능을 증명한다 / 막히면 이유와 검증된 대안이 나온다.
- **담지 않는 것**: 확정 뒤 운영 중 변경, 다음 주로 이어지기, 칸 고정.

**파트별 필요 인원** (정확히 이 인원)

| | 오픈 | 미들 | 마감 |
|---|---|---|---|
| 홀 평일 | 2 | 1 | 3 |
| 홀 주말 | 2 | 2 | 4 |
| 주방 평일 | 2 | 1 | 2 |
| 주방 주말 | 2 | 1 | 3 |

저녁은 마감조만 맡으므로 마감을 가장 두껍게 두고, 주말 저녁을 가장 바쁜 시간으로 본다. 일요일 홀은 필요 인원(8명)과 가능 인원(8명)이 같다. 일요일 홀 가능자를 한 명이라도 빼면 해가 사라진다.

**말로 적을 필요 인원** (네 문장이 규칙 12개가 된다)
- 홀은 평일에 오픈 2명, 미들 1명, 마감 3명
- 홀은 주말에 오픈 2명, 미들 2명, 마감 4명
- 주방은 평일에 오픈 2명, 미들 1명, 마감 2명
- 주방은 주말에 오픈 2명, 미들 1명, 마감 3명

**말로 적을 규칙**
1. 마감 다음 날 오픈은 안 되게
2. 일주일에 이틀은 꼭 쉬게
3. 홀 마감과 주방 마감에는 리더가 꼭 1명씩 있어야 해
4. 마감에는 파트별로 신입이 1명까지만
5. 마감은 파트 안에서 돌아가면서 고르게
6. 근무 일수도 고르게

**이야기의 장치**: 화요일에 주방 마감을 설 수 있는 리더가 없다. 서민호와 배지수는 화요일에 일할 수 없고, 조현우는 16시까지만 가능하다. 그래서 세 사람의 가능 시간과 규칙 3은 함께 지킬 수 없다. 가능 시간은 직원이 정한 것이라, 매니저가 바꿀 수 있는 것은 규칙 3뿐이다.

서민호의 화요일은 따로 휴가로 넣지 않고 가능 시간에서 비운다. 직원이 매주 가능 시간을 내는 흐름에서는 휴가인 날을 칠하지 않는 것이 자연스럽다.

## 최적화 문제

직원 20명 × 7일 × 근무 4종으로 변수 560개를 푼다.

- **변수**: `x[e,d,s] ∈ {0,1}`, 직원 e가 d일에 근무 s를 하면 1
- **hard**: 하루 근무 하나 / 가능 시간이 근무 시간을 다 덮을 때만 배정 / 파트별 필요 인원 / 마감 다음 날 오픈 금지 / 주 2일 이상 휴무 / 파트별 마감에 리더 1명 이상 / 파트별 마감에 신입 1명 이하
- **목적**: `5 × (홀 마감 횟수 최대−최소) + 5 × (주방 마감 횟수 최대−최소) + 5 × (근무 일수 최대−최소)` 최소화. 가중치 5는 앱이 고르게 규칙을 중요도 "낮음"으로 번역했을 때의 값이다.

| 풀이 | 장면 | 문제 | 결과 |
|---|---|---|---|
| P1 | 8 | 위 조건 전부 | 해 없음 |
| P2 | 10 | 주방 마감 리더를 벌점으로 바꿈: `Σ 주방 리더 x[e,d,C] + miss[d] ≥ 1`, 목적에 `+ 10 × Σ miss[d]` (중요도 "보통") | 최적해 |

P1은 손으로도 증명된다. 화요일 주방 마감 리더 조건이 `0 + 0 + 0 ≥ 1`이 된다.

## 검증 결과

**독립 모델 (2026-11-03, 현재 데이터)**: 위 수식을 그대로 옮긴 CP-SAT 모델로 풀었다.
- P1은 해 없음이다. 함께 지킬 수 없는 최소 묶음은 서민호·배지수·조현우 가능 시간과 주방 마감 리더다.
- P2는 최적해, 목적값 45다. 홀 마감 차이 3, 주방 마감 차이 3, 근무 일수 차이 1, 리더 없는 주방 마감은 화요일 하루다.
- 같은 점수의 근무표가 여러 개라, 칸 배치는 실행마다 달라질 수 있다.

아래 앱 API와 화면 시험은 이전 데이터로 했다. 이전 데이터는 근무조 09~16 / 12~20 / 16~23, 주말 필요 인원 홀 2/3/3·주방 2/2/2, 서민호 화요일을 휴가 예외로 넣은 버전이다. 현재 데이터로 다시 시험해야 한다.

**앱 API (2026-11-03)**: 화면 대신 앱과 같은 요청을 만들어 실제 번역(`/translate`), 풀이(`/solve`), 설명(`/explain`)을 호출했다.

**확인된 문제**
- **못 지킨 규칙 3건**: 제안 적용 후 화면에는 "리더 마감 0명" 1건과 "마감 개수 편차 3"(홀, 주방) 2건이 함께 나온다. 장면 11에서 "포기한 것은 화요일 하루"만 말하면 화면과 어긋나 보일 수 있다.
- **신입을 id로 고정**: 규칙 4는 신입 태그를 쓰지 않고 지금의 신입 4명을 이름으로 묶었다. 나중에 신입 태그를 바꿔도 규칙은 따라가지 않는다.
- **한 문장, 두 카드**: 규칙 3과 4가 카드 2장씩으로 나뉘지만 원문은 같다. 근무표 없음 패널에서 같은 문장이 두 번 보이거나 어느 파트 규칙인지 헷갈릴 수 있다.
- **설명의 어색한 문장**: "배지수은" 같은 조사 오류와, 뜻이 흐린 마지막 문장이 있었다.

**화면 (2026-11-03)**: 테스트 계정에 한강 다이닝을 넣고 Playwright로 ② 매장 조건 → ③ 근무표 없음 → 제안 수락까지 조작했다. 필요 인원 중 "홀 평일" 한 문장만 화면에서 입력하고, 나머지는 미리 번역해 넣었다.

| ② 하단 안내 | 필요 인원을 모두 넣었는데도 "필요 인원 없이 만들면 인원을 맞추지 않아요"가 보인다 |

**화면에서 확인된 문제**
- **모순된 요약**: "규칙을 모두 지켰어요" 옆에 "못 지킨 규칙 3"이 보인다. 반드시 규칙은 다 지켰다는 뜻이지만 영상에서는 모순으로 읽힌다.
- **틀린 안내**: 파트별 필요 인원을 규칙으로 넣으면 "필요 인원 없이 만들면…" 안내가 잘못 뜬다.
- **빈 요약표**: ② 요약표의 인원 칸이 비어 있어, 필요 인원을 넣었는지 한눈에 보이지 않는다.
- **어느 파트인지 모호한 제안**: 제안 카드의 원문은 "홀 마감과 주방 마감에는…" 전체라서, 주방 규칙만 바뀐다는 것이 카드에서 드러나지 않는다.
- **번역 결과의 변동**: 신입 규칙은 API 시험에서 직원 id로, 화면 시험에서 태그("신입", 다른 파트 제외)로 번역됐다. 실행마다 표현이 달라진다.

**고친 것 (2026-11-03)**: 현재 데이터로 화면을 다시 돌려 확인했다.
- **모순된 요약**: 배지를 "반드시 규칙을 모두 지켰어요"로, 칸 이름을 "못 지킨 가능하면 규칙"으로 바꿨다.
- **틀린 안내**: 직급별 배치 규칙도 필요 인원으로 쳐서 안내가 뜨지 않는다.
- **빈 요약표**: 칸에 "주방 2명 · 홀 2명"처럼 직급별 인원을 보여 준다.
- **끊어 읽히는 규칙 문구**: "리더 직급 홀 빼고"를 "리더 직급(홀 제외)"로 바꿨다.

**아직 시험하지 않은 것**
- **나머지 화면**: 장면 1~6과 12.
- **반복 실행**: 번역과 제안은 두 번씩만 돌렸다.

## 녹화 조건

- **로그인**: Google 로그인은 자동화할 수 없어 1번을 로그인 화면에서 끊고, 테스트 계정 세션으로 빈 매장부터 이어 찍는다.
- **빈 매장**: 녹화 전에 테스트 계정의 매장을 지운다. 직원 1명만 화면에서 입력하고, 나머지 19명의 가능 시간은 스크립트가 제출 함수로 넣는다.
- **날짜**: 위 날짜는 예시다. 실제 근무표 첫날은 녹화일 기준으로 정해진다. 가능 시간은 요일 기준으로 넣으므로 서민호가 비우는 날은 항상 둘째 날(화요일)이다.
- **제안 고르기**: 제안 제목과 설명은 LLM이 써서 매번 달라진다. 스크립트는 코드가 쓰는 변경 문구 "반드시 → 가능하면"으로 카드를 찾는다. 그 카드가 없으면 그 실행은 버린다.
- **LLM 대기**: 카드와 설명을 기다리는 구간은 편집으로 줄인다. 근무표 생성 장면은 줄이지 않는다.
- **해의 변동**: 같은 점수의 답이 여러 개라 근무표 모양은 녹화마다 다를 수 있다. 자막에 특정 배정을 쓰지 않는다.
- **가독성**: 20명 × 7일 표는 글자가 작다. 9~11번은 표와 패널을 확대한다.
- **입력 순서**: 지금 앱은 명단을 먼저 넣어야 시작할 수 있어 장면 2가 3, 7보다 앞선다. 매장 조건을 먼저 넣는 흐름으로 앱을 바꾸면 순서도 바꾼다.
- **개인정보**: 테스트 계정 이메일은 가짜 주소로 가린다.
