# 매장 직원 스케줄로 전환 설계 (2026-10-30)

간호사 근무표를 스케줄 근무 매장의 직원 근무표로 바꾼다. 같은 저장소에서 전환하고, 간호 버전은 태그 `nurse-final`로 남긴다.
실제 사용자, 저장 데이터, 배포가 없으므로 하위 호환과 데이터 이전은 하지 않는다.

## 유지
- 식 언어(ADR-019), CP-SAT 솔버, 번역과 충돌 설명, 재풀이 검증, 무상태 백엔드, 문서 1개 + RLS 저장
- 칸마다 근무 코드 하나, 복합 코드, 이월, 누적 부담, 운영 중 변경, 포트폴리오 프로토타입이라는 목표

## 결정

### 1. 근무는 사용자가 정한 근무조 중에서 배정한다
- 솔버는 사람과 날짜마다 근무조 하나나 휴무를 고른다. 임의의 시간은 만들지 않는다.
- 기본 근무조: 오픈(`A`) 09:00~15:00, 미들(`M`) 12:00~18:00, 마감(`C`) 17:00~23:00, 각 실근무 6시간, 휴무(`O`). 이름과 시각은 사용자가 바꾼다.
- `ShiftDef`의 `start`(지금은 표시용)에 `end`를 더한다. 복합 코드가 아니면 둘 다 받는다.
- `hours`는 실근무 시간으로 따로 둔다. 쉬는 시간 때문에 시각 차이와 다를 수 있다.
- `parts`는 복합 코드가 세는 근무조다. 시간 구간이 아니다. 쪼개기 근무도 복합 코드로 표현한다.

### 2. 시간대 필요 인원은 근무조 조합으로 세운다
- "12~15시 최소 3명"은 그 시간을 덮는 근무조를 세는 규칙이다(오픈 + 미들 ≥ 3).
- LLM이 근무조 시각을 보고 코드 집합을 고른다. 식 언어와 솔버는 바꾸지 않는다.
- 카드 문장과 예시 판정으로 사람이 확인한다. eval에 케이스를 넣어 정확도를 잰다.
- 근무 시각 겹침을 솔버가 직접 계산하는 기능은 계속 범위 밖이다.

### 3. 용어를 코드까지 모두 바꾼다
| 지금 | 화면 | 코드 |
|---|---|---|
| 수간호사 | 매니저 | - |
| 병동 | 매장 | `shop`, `ShopConfig`, 테이블 `shops` |
| 간호사 | 직원 | `employee`, `Employee`, `employees` |
| 나이트 전담 | 없음 | 삭제 |

- 코드에 `store`를 쓰지 않는다. Zustand의 `lib/store.ts`와 헷갈린다.
- 가명은 `N01`에서 `E01`로 바꾼다.

### 4. 간호 전용 개념을 지운다
- `NIGHT_ONLY_TAG`, 나이트 전담 기본 규칙, 완화 거부 처리
- 직원의 `years`와 셀렉터 `min_years`·`max_years`, CSV의 연차 열. 경력 구분은 태그로 표현한다.
- 이력에서 쓰이던 옛 형식: `backend/domain/legacy.py`, `convert.py`, `lib/migrate.ts`의 v4·v5 변환과 관련 골든 파일. 테스트 도우미(`tests/rules.py`, `block_oracle.py` 등)가 이들을 쓰므로 식 규칙으로 옮긴 뒤 지운다.

### 5. 매장 쪽 기본값
- 기간 단위 기본값은 1주다.
- 예시는 주 근무 시간 규칙과 "오픈에 리더 1명"을 쓴다. 노동법 판단은 하지 않고, 사용자가 말한 규칙만 지킨다.
- 공휴일 처리와 주말 정의는 그대로 둔다.
- 태그는 직원 표의 선택 입력으로 남기고 추천 태그는 두지 않는다.

### 6. 3단계 흐름 (사용자 결정)
스케줄 매니저가 쓰는 서비스다. 근무표마다 ① 가능 시간 → ② 매장 조건 → ③ 근무표 순서다.
- 매니저가 직원별 링크를 복사해 직접 공유한다. 자동 발송은 없다.
- 직원은 로그인 없이 캘린더에서 가능 시간대를 드래그한다(06:00~24:00, 30분 칸, 데스크톱 웹).
- 모두 제출한다고 가정한다. 미제출 경고와 처리는 두지 않는다. 제출 전이면 가능 시간이 없으므로 배정되지 않는다.
- 게스트 모드를 없앤다. 링크가 서버 데이터를 요구한다.
- 가능 시간이 근무조 시각을 완전히 덮는 칸만 배정한다. 코드가 판정해 반드시 규칙으로 바꾸고, 완화 제안 대상에서 뺀다. 칸 고정은 우선한다.

## 문서 순서
1. `CLAUDE.md`, `docs/PRD.md`, `docs/ARCHITECTURE.md`, `docs/UI_GUIDE.md`, `docs/BROWSER_TEST_SCENARIOS.md`를 매장 기준으로 고친다.
2. `docs/ADR.md`에 ADR-020(이 문서의 결정)을 더하고, ADR-010 등 간호 전제 항목에 대체 표시를 단다. 옛 ADR 본문은 고치지 않는다.
3. harness가 매 step에 문서를 넣으므로 코드 작업 전에 끝낸다.

## 구현 phase 초안
초기 초안이다. 실제 순서는 `phases/6-shop-pivot`, `phases/7-availability`를 따른다.

1. `remove-legacy`: 옛 형식 변환과 간호 전용 개념 삭제, 테스트 도우미 이전
2. `rename-domain`: 백엔드 `shop`·`employee` 이름 변경, 타입 재생성
3. `shift-times`: `end` 추가, 기본 근무조, 시각을 LLM 문맥에 전달
4. `llm-shop`: 프롬프트, eval 데이터셋을 매장 말투로 교체, 실제 eval 실행
5. `client-rename`: `lib/`·컴포넌트 이름 변경, 저장 문서 버전 초기화, `shops` 마이그레이션
6. `login-required`: 게스트 모드 제거, 로그인 화면, 매장 준비
7. `availability-backend`: `availability_links`와 토큰 DB 함수, `lib/availability.ts`, explain 완화 거부
8. `availability-ui`: 직원 드래그 캘린더, 링크 표
9. `flow-steps`: 근무표 작성 3단계, 매장 조건 통합
10. `samples-e2e`: 샘플 매장, 데모, 랜딩 문구, 테스트 계정, e2e, 벤치
