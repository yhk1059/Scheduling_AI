# 흐름 재설계 (2026-10-29, 확정)

`notes/flow-map-2026-10-29.md`(지금 흐름)를 바탕으로, 처음 설정과 근무표(작성·확정·운영 중 변경)를 버튼 단위로 다시 나눈 초안이다.
"단계" = 버튼을 누르면 다음으로 넘어가는 화면 하나. ★ 표시는 2026-10-29에 추천안대로 확정한 결정이다.

## 0. 화면 구성 (바뀐 뒤)

```
/app
├── 시작 화면        (그대로)
├── 처음 설정        새 화면. 근무표를 한 번도 만들지 않은 병동에서만 보인다
│     ① 병동·명단 → ② 필요 인원 → ③ 병동 규칙 → [첫 근무표 만들기]
├── 병동 홈          탭 [근무표]. 운영 중 카드의 입구가 [변경 입력]으로 바뀐다
├── 병동 설정        탭 [명단·필요 인원] [병동 규칙]. 고칠 때만 쓴다. [첫 근무표 만들기] 없음
├── 근무표 작성      작성 중인 근무표. 스테퍼 ① 요청 → ② 근무표, 끝 버튼 [확정]
└── 확정 근무표      확정된 근무표(운영 중·시작 전·지난). 변경 입력이 맨 위
```
- `view`에 `setup`(step 1~3)과 `confirmed`(periodId)가 추가되고, `period`의 step은 1~2가 된다.
- 근무표를 열면 상태로 화면이 정해진다: 작성 중 → 근무표 작성, 확정 → 확정 근무표.

## 1. 처음 설정

| 단계 | 화면 | 하는 일 | 다음으로 가는 버튼 | 들어가는 방법 |
|---|---|---|---|---|
| ① | 처음 설정 › 병동·명단 | 병동 이름, 근무표 주기, 명단 붙여넣기/CSV/빈 표 → [표로 만들기] → [명단에 반영] | [다음] (간호사 1명 이상일 때) | 랜딩 [내 병동으로 시작하기], 시작 화면, 근무표가 없는 병동으로 재방문 |
| ② | 처음 설정 › 필요 인원 | 평일 / 주말·공휴일 D·E·N 최소·최대 | [다음] (6칸 모두 입력) · [이전] | ①의 [다음] |
| ③ | 처음 설정 › 병동 규칙 | 말로 규칙 적기(예시 Text 버튼) → [규칙 만들기] → 카드 [적용]/[모두 적용] | [첫 근무표 만들기] · [이전] | ②의 [다음] |
| → | 근무표 작성 › ① 요청 | (아래 2절) | | ③의 버튼 |

- 위에 설정용 스테퍼(① 병동·명단 ② 필요 인원 ③ 병동 규칙)를 둔다. 탭 줄([근무표] [병동 설정])은 처음 설정 중에 숨긴다.
- 재방문하면 아직 못 끝낸 첫 단계에서 다시 연다(명단 없음 → ①, 필요 인원 없음 → ②, 그 밖 → ③).
- ★ ③에서 적용한 규칙이 0개여도 [첫 근무표 만들기]를 누를 수 있다. 대신 버튼 옆에 "규칙 없이 만들면 필요 인원만 지켜요" 한 줄. 적용 대기 카드가 남아 있으면 "적용하지 않은 규칙 2개는 빠져요".
- 첫 근무표를 만든 뒤에는 처음 설정이 다시 보이지 않는다. 이후 수정은 병동 설정 탭에서.

## 2. 근무표 작성 (확정 전)

| 단계 | 화면 | 하는 일 | 다음으로 가는 버튼 | 들어가는 방법 |
|---|---|---|---|---|
| ① | 근무표 작성 › 요청 | 맨 위 준비 요약 한 줄(날짜 · 공휴일 n일 · 간호사 n명 · 지난 근무 이어짐) + [바꾸기]로 펼침. 아래 요청 입력 → 카드 → [적용]/[모두 적용]. 이 근무표에 걸리는 병동 규칙(접힘) | [다음] | 홈 [12월 근무표 만들기] / [이어서 하기], 처음 설정 ③ |
| ② | 근무표 작성 › 근무표 | [근무표 만들기] → 결과·요약·최근 4주 근거·통계. 칸 고정 → [다시 만들기]. 근무표 없음이면 이유 + 검증된 제안 [수락] / [이번 근무표에서만 끄기] | [확정] · [이전] | ①의 [다음], 홈 [근무표 확인하기] |
| → | 확정 근무표 | (아래 3절) | | ②의 [확정] |

- 준비 요약을 저절로 펼치는 경우: 명단이 지난 근무표와 다를 때, 지난 근무표가 바뀌었을 때(배너). 그 밖에는 접힌 한 줄.
- ★ 첫 근무표의 공휴일·지난 근무 입력: 요약 줄에서 [바꾸기]로 펼친다(기본 접힘). 공휴일이 0일이면 요약에 "공휴일 없음"을 그대로 보여 준다.
- ★ 확정은 단계가 아니라 ②의 끝 버튼이다. 누르면 확정 근무표 화면으로 옮겨 간다. 스테퍼는 ① 요청 ② 근무표 두 칸.

## 3. 확정 근무표 (확정 후, 운영 중 변경)

| 단계 | 화면 | 하는 일 | 다음으로 가는 버튼 | 들어가는 방법 |
|---|---|---|---|---|
| ① | 확정 근무표 | 제목 + 배지(운영 중/확정) + 마지막 확정 시각 + [CSV 받기]. 맨 위에 변경 입력 바("최지훈 이번 주 병가"). 아래 근무표(지난 날 잠김, 오늘 밑줄)·통계. 게스트는 첫 확정 직후 저장 안내 배너 | [요청 만들기] | 작성 ②의 [확정], 홈 운영 중 카드 [변경 입력](입력 바에 포커스), 홈 지금 할 일 [열기](확정된 다음 근무표) |
| ② | 확정 근무표 (변경 중) | 변경 카드 확인 → [적용] → 최소 변경으로 다시 만듦 → 바뀐 칸 주황 테두리, "1명 3칸 변경" | [다시 확정] (+ ★ [변경 취소] Text: 마지막 확정본으로 되돌림) | ①에서 카드 [적용] |
| → | 확정 근무표 | 새 확정본 기록. ①로 돌아감 | | [다시 확정] |

- 스테퍼가 없다. 요청 단계로 돌아가지 않는다. 확정 뒤 생긴 요청은 모두 변경 입력으로 넣는다(시작 전 확정 근무표 포함).
- 지난 근무표(끝난 기간)는 같은 화면에서 변경 입력을 숨긴 보기 전용 + [CSV 받기].
- 지난 근무표가 바뀌어 이어지는 근무가 달라지면 배너 + [다시 만들기](최소 변경) → [다시 확정].

## 5. 확정한 결정 (2026-10-29)
1. 처음 설정은 3단계(병동·명단 / 필요 인원 / 병동 규칙).
2. 규칙 0개로도 [첫 근무표 만들기] 가능. 버튼 옆 안내 한 줄, 적용 대기 카드가 남으면 빠진다고 안내.
3. 확정은 단계가 아니라 작성 ②의 끝 버튼. 누르면 확정 근무표 화면으로. 스테퍼는 ① 요청 ② 근무표.
4. 준비 요약은 기본 접힘. 명단이 바뀌었거나 지난 근무표가 바뀌었을 때만 저절로 펼침. 첫 근무표의 공휴일·지난 근무도 [바꾸기]로.
5. 확정 뒤에는 요청 단계로 돌아가지 않고 변경 입력만. [다시 확정] 전 [변경 취소] Text를 둔다. 끝난 근무표는 보기 전용.

## 6. 문서 반영 범위
- **PRD**: "화면" 절(앱 하위 화면 목록에 처음 설정·근무표 작성·확정 근무표), J0 끝(빈 병동 설정 → 처음 설정 ①), J1(순서를 3단계로, [첫 근무표 만들기]는 ③에만, 규칙 0개 허용), J2(요청(준비 요약) → 근무표 → [확정] → 확정 근무표), J3(명단 점검·이월 확인은 요약 한 줄, 바뀐 게 있을 때만 펼침), J4(홈 운영 중 카드 [변경 입력] → 확정 근무표, [변경 취소], 끝난 근무표는 보기 전용).
- **UI_GUIDE**: 화면 구조 트리와 "이동"(처음 설정 중 탭 줄 숨김), "처음 쓰는 경우" 문단 → 새 "처음 설정" 절, 병동 홈(진행 단계 요청 → 근무표 → 확정, 운영 중 카드 버튼), "기간 작업" → "근무표 작성"(스테퍼 2칸, 준비 요약), "③ 근무표의 버튼" 표를 작성 ②(만들기 전/만든 뒤)와 새 "확정 근무표" 절(변경 없음/변경 있음/끝난 근무표)로 나눔, 병동 설정에서 [첫 근무표 만들기] 삭제, 스테퍼 컴포넌트 위치에 처음 설정 추가.

- **BROWSER_TEST_SCENARIOS**: 처음 설정·확정 근무표 시나리오.
