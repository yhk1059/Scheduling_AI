# UX 점검 (2026-10-29)

처음 쓰는 사람 시선으로 게스트 흐름을 따라감: 랜딩 → 시작 → 샘플 → 병동 설정(명단·규칙) → 병동 홈 → 11월 ①준비 ②요청 ③근무표 → [확정].
로컬 dev 서버, Supabase env 있음, 로그인 안 함.

**못 본 것**: 다음 기간·이월·누적 부담·운영 중 변경·다시 확정(게스트는 [확정]이 로그인 대화상자로 막힘), 로그인 흐름, 모바일 폭.

## A. 흐름이 막히거나 잘못 보이는 문제 (먼저 결정 필요)

| # | 화면 | 문제 | 왜 문제인가 |
|---|---|---|---|
| A1 | ③ 근무표 → [확정] | 게스트는 확정할 수 없음. 로그인 대화상자가 뜨고 [CSV만 받기]뿐 | 샘플 체험이 ③에서 끝남. 이번 phase의 핵심(다음 기간, 이월, 최근 4주 부담, 운영 중 변경)을 로그인 없이는 아무것도 못 봄 |
| A2 | ③ 근무표 (샘플) | 나이트 전담 2명(문가람·배수아)이 **30일 연속 나이트, 휴무 0일**. 통계에 "최대 연속 근무 30일" | 첫 결과가 비현실적이라 신뢰를 잃음. 샘플에 병동 규칙이 0개(필요 인원 6개뿐)라 생김 |
| A3 | 시작 화면 | "샘플 병동(15명)과 **병동 규칙을 불러와요**" | 실제 샘플 규칙은 0개. 문구와 실제가 다름 |
| A4 | 병동 홈 | 근무표를 생성한 뒤에도 "초안 / [이어서 작성]"만 보임 | 생성했는지, 다음에 뭘 할지 알 수 없음 |
| A5 | 홈 vs ② 요청 | 홈 "병동 규칙 1개", ② "이 기간에 적용될 병동 규칙 7개" | 같은 것을 다르게 셈(필요 인원 6개 포함 여부) |

## B. 개발자 용어가 그대로 노출됨

| 지금 문구 | 어디 | 사용자가 겪는 것 |
|---|---|---|
| 기간 · 다음 기간 · 최근 기간 · 기간 단위 · 달력 월 | 홈, 상단 바, 설정 | "11월 근무표"라고 하면 될 것을 추상 개념으로 말함 |
| 초안 | 홈, 기간 제목 | 무엇의 초안인지, 생성 전인지 후인지 구분 안 됨 |
| 활성 / 비활성으로 / 명단 점검 "명단 활성 15명" | 설정, 홈, ① | 휴직·퇴사 처리라는 뜻이 안 보임 |
| 이월 근무 · 반영 · "이름, 그다음 오래된 날부터 근무 코드(D/E/N/O)" | ① 준비 | 무엇을 넣으라는지 모름 |
| 해석 · 변환 | 규칙·요청 입력, 명단 붙여넣기 | 버튼이 무슨 일을 하는지 불명확 |
| hard / soft 토글 | 규칙·요청 카드 | 영어 + 개념 설명 없음 ("반드시 / 가능하면") |
| `n01 이영희 · 11/15~11/17 · O`, `N 뒤 O 1일`, `N 기피` | 카드 요약 | 내부 id(n01)와 코드가 노출됨 |
| 해 상태 · 해 있음 · soft 위반 · 다시 풀어요 | ③ 요약 | 솔버 용어 |
| 평균 대비 편차 (-0.40 등) · 4주 N · 4주 주말 · N전담 | ③ 그리드·통계 | 숫자의 의미를 설명하지 않음 |

## C. 화면 구조

- **병동 홈**: 다음 기간 카드와 최근 기간 표가 같은 내용을 두 번 보여 줌. 지금 할 일과 진행 정도가 안 보임.
- **핵심 기능이 숨어 있음**: "말로 규칙 입력"이 제품의 핵심인데 병동 설정의 두 번째 탭에 있음. 샘플에는 규칙이 없어 체험 중에 볼 일이 없음.
- **병동 설정 명단**: 줄마다 빨간 [삭제]와 [비활성으로]가 나란히 있는데 차이를 알 수 없음. 저장 버튼이 없어서 자동 저장되는지 모름.
- **① 준비**: 첫 기간에는 대부분 필요 없는 이월 근무 붙여넣기가 기본으로 보임.
- **② 요청**: 카드를 하나씩 [적용]해야 함. 적용하면 카드가 다른 칸으로 옮겨져 화면이 튐. "모두 적용"이 없음.
- **③ 근무표**:
  - 생성 전에 "칸을 눌러 고정하면…" 설명이 먼저 나옴.
  - 생성 후에도 [생성]이 Primary이고 [확정]은 보조 버튼. 다음에 할 일은 확정인데 강조가 반대.
  - 통계 표가 11열이고, 첫 기간에는 "최근 4주" 열이 전부 0.
- **로그인 진입점이 두 번**: 시작 화면에 상단 바 [Google로 로그인]과 카드 [Google로 로그인]이 동시에 있음.

## D. 랜딩

- "한 달 근무표를 짭니다": 이제 1주·2주·4주도 지원함.
- 독자가 섞여 있음: 수간호사 대상 문구와 LLM·CP-SAT·Pydantic·eval 표 같은 기술 설명이 한 페이지에 있음(포트폴리오가 목적이면 괜찮음. 결정 필요).

## 결정 (2026-10-29)

1. **게스트도 확정 가능 (A1)**: 확정·다음 기간·운영 중 변경까지 브라우저 안에서 모두 된다. 로그인은 상단 바와 확정 직후의 "저장하려면 로그인" 권유로만 보이고, 흐름을 막지 않는다. PRD J2와 ADR-014의 "확정 = 로그인" 문장을 고친다.
2. **앱과 랜딩 모두 수간호사 기준**: 앱 문구를 현장 말로 바꾼다("11월 근무표", "반드시/가능하면" 등). 랜딩의 기술 설명(LLM·CP-SAT·eval)은 줄이거나 아래로 내린다.
3. **샘플 = 규칙 + 요청 + 확정된 10월 (A2·A3)**: 현실적인 병동 규칙(나이트 후 휴무, 최대 연속 근무, 월 최소 휴무 등), 11월 요청 2~3개, 확정된 10월 근무표를 넣는다. 11월을 열면 이월과 최근 4주 부담이 바로 보인다.
