# Step 8: e2e-ux

## 읽어야 할 파일

먼저 아래 파일들을 읽고 프로젝트의 아키텍처와 설계 의도를 파악하라:

- `/CLAUDE.md`
- `/docs/PRD.md` (사용자 저니 J0~J7, **데모 저니(최종 수용 기준)**)
- `/docs/ADR.md` (ADR-013 e2e, ADR-014 게스트)
- `/docs/UI_GUIDE.md` ("화면 구조", "병동 홈", "기간 작업", **"문구"**, "접근성")
- `/docs/BROWSER_TEST_SCENARIOS.md` (지금 시나리오: 옛 문구·옛 샘플 기준)
- `/e2e/entry.spec.ts`, `/e2e/journey.spec.ts`, `/playwright.config.ts`
- `/lib/sample.ts` (step 3), `components/` 전체 (step 4~6에서 바뀐 접근성 이름)

## 배경

step 1~7에서 게스트 확정, 오늘 기준 샘플(운영 중 이번 달 + 작성 중 다음 달), 화면 문구가 모두 바뀌어 기존 시나리오 문서와 Playwright spec이 맞지 않는다. 이 step은 **게스트 모드** 기준으로 문서와 spec을 다시 맞추고 e2e를 한 번 실행한다. 로그인·Supabase는 ADR-014에 따라 범위 밖이다.

## 작업

### 1. `docs/BROWSER_TEST_SCENARIOS.md` 개정
- 기존 형식(대상의 접근성 역할과 이름, 값, 검증)과 시계 고정 `2026-10-28T09:00:00+09:00`을 유지한다.
- 시나리오를 새 화면·문구로 바꾸고 아래를 포함한다.
  - S1 랜딩 → 앱, S2 시작 화면(카드 2개, 로그인 카드 없음)
  - **샘플 체험**: 샘플 → 홈에 "10월 근무표 · 운영 중" 카드와 지금 할 일(11월, 요청 3개) → 11월 ① 준비에 지난 근무 마지막 며칠 표 → ③ [근무표 만들기] → 최근 4주 열과 근거 한 줄 → [확정](게스트) → 저장 안내 배너 → 홈에서 [12월 근무표 만들기]가 Primary
  - **샘플 운영 중 변경**: 10월 근무표 → 지난 날짜 잠금 → 병가 입력 → 최소 변경 → [다시 확정] → 11월에 "지난 근무표가 바뀌어…" 배너
  - **내 병동 첫 근무표**(데모 저니 1~7): 명단 붙여넣기 → 필요 인원 → 병동 규칙 3개 → 첫 근무표 ① 공휴일 → ② 요청 2개 → ③ 만들기(최근 4주 열 없음) → 근무표 없음과 제안 수락 → 칸 고정 → 확정
  - 이어서 하기(새로고침 후)
- 화면 글자 기준 검증에 옛 용어(기간, 초안, hard/soft, 해 있음 등)가 남지 않게 한다.

### 2. `e2e/*.spec.ts` 개정
- 문서 시나리오와 1:1로 맞춘다. 파일 분리는 재량.
- LLM 결과는 카드 제목과 핵심 파라미터만 검증한다(기존 방식).
- 화면에 개발 용어가 보이지 않는지 한 번 검사한다(예: 주요 화면에서 `hard`, `soft`, `해 있음`, `n0[0-9]` 텍스트가 없음).

## Acceptance Criteria

```bash
npx playwright test --list
npm run test
npm run build && npm run lint
```

## 검증 절차

1. 위 AC 커맨드를 실행한다.
2. `npm run test:e2e`를 한 번 실행한다(실제 Anthropic API, ADR-013).
   - 앱 버그로 실패하면 앱을 고친다(이 step에서 컴포넌트 수정 허용, 범위는 버그 수정까지).
   - LLM 응답 변동으로 실패한 시나리오는 재실행으로 확인하고, 결과를 summary에 적는다.
3. 아키텍처 체크리스트를 확인한다:
   - e2e가 `npm run test`나 Stop 훅에 들어가지 않았는가(ADR-013)?
   - LLM을 mock하지 않았는가?
   - 로그인 흐름을 자동화하지 않았는가(ADR-014)?
4. 결과에 따라 `phases/3-ux/index.json`의 해당 step을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약 + e2e 실행 결과"`
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - `ANTHROPIC_API_KEY`가 없거나 브라우저 설치가 막혀 e2e를 실행할 수 없으면 AC만 통과시키고 completed로 두되, summary에 "e2e 미실행: 사유"를 적는다.

## 금지사항

- e2e를 `npm run test`나 Stop 훅에 넣지 마라. 이유: ADR-013.
- 테스트를 통과시키려고 접근성 이름을 테스트 전용 값(`data-testid` 등)으로 바꾸지 마라. 이유: 시나리오는 접근성 역할과 이름으로 대상을 찾는다.
- 기능을 새로 넣지 마라. 이유: 이 step은 시나리오 정비와 버그 수정까지다.
- 기존 테스트를 깨뜨리지 마라.
