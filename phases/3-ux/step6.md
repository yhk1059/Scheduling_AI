# Step 6: ui-home-start

## 읽어야 할 파일

먼저 아래 파일들을 읽고 프로젝트의 아키텍처와 설계 의도를 파악하라:

- `/CLAUDE.md`
- `/docs/PRD.md` (J0, J3, J7)
- **`/docs/UI_GUIDE.md`** ("화면 구조"의 시작 화면·근무표 이름, **"병동 홈"** 전체, "레이아웃"의 앱 상단 바, "반복 사용 컴포넌트"의 저장 상태·계정·대화상자, "문구")
- `/lib/wording.ts` (step 2: `nextTask`, `scheduleName`, `unitShort`, `wardRuleCount`)
- `/lib/store.ts` (`homeSummary`, `createPeriod`, `go`)
- `/components/WardHome.tsx`, `/components/StartScreen.tsx`, `/components/AppShell.tsx`, `/components/Account.tsx`

## 배경

UX 점검에서 사용자가 병동 홈을 보고 "무슨 말인지 하나도 모르겠다"고 했다. 다음 기간 카드와 최근 기간 표가 같은 내용을 두 번 보여 줬고, 생성 후에도 "초안 / [이어서 작성]"이라 진행 상황이 보이지 않았으며, 홈의 규칙 수(1개)와 요청 단계의 규칙 수(7개)가 달랐다. 시작 화면에는 [Google로 로그인]이 상단 바와 카드에 두 번 있었다.
UI_GUIDE "병동 홈"이 새 구조를 정했다: **제목 줄 요약 → 운영 중 근무표 카드 → 지금 할 일 카드 → 지난 근무표 표.**

## 작업

### 1. 병동 홈 (`WardHome.tsx`)
- **제목 줄**: 병동 이름(페이지 제목) + 오른쪽 "간호사 15명 · 병동 규칙 6개 · 한 달 단위"(`wardRuleCount`, `unitShort`) + [병동 설정] Text.
- **운영 중 근무표 카드**(있을 때만): `scheduleName`, `운영 중` 배지, "마지막 확정 10/28 14:32"(mono), [열기] Secondary.
- **지금 할 일 카드**(`nextTask`):
  - 진행 단계 한 줄(① 준비 → ② 요청 → ③ 근무표 → 확정, 끝난 단계는 체크 SVG). 스테퍼 스타일을 작게 재사용해도 된다. 단계는 누를 수 없다(표시만).
  - 상태 문장과 버튼은 UI_GUIDE "병동 홈" 표대로. 버튼 하나, 홈의 유일한 Primary.
  - 첫 근무표가 없는 병동은 "첫 근무표를 만들 차례예요" + [{이름} 근무표 만들기].
  - 병동이 준비되지 않았으면(필요 인원 없음 등) 지금처럼 병동 설정으로 안내한다.
- **지난 근무표 표**: 확정한 지난 근무표만(지금 할 일 카드·운영 중 카드와 같은 근무표는 빼기). 열은 근무표 이름, 확정 시각. 행을 누르면 그 근무표. 비어 있으면 "확정한 근무표가 여기에 쌓여요" 한 줄.
- 기존 "다음 기간 카드", "최근 기간 표", 하단 병동 요약 한 줄은 없앤다.

### 2. 시작 화면 (`StartScreen.tsx`)
- 카드 두 개 [샘플로 체험하기], [내 병동으로 시작하기](+ 입력이 있으면 [이어서 하기]). Google 로그인 카드는 없앤다.
- 카드 아래 "로그인하면 다른 기기에서도 이어서 쓸 수 있어요" 한 줄과 [개인정보처리방침] Text 링크(`supabaseConfigured`가 false면 이 줄과 링크 모두 숨김).
- 샘플 설명 문구는 실제 샘플과 맞춘다: "간호사 15명과 병동 규칙 6개, 이번 달 확정 근무표가 들어 있어요. 다음 달 근무표를 바로 만들어 볼 수 있어요." 같은 식(숫자는 데이터에서 계산).
- 확인 대화상자의 화면 이름 표기("기간 작업" 등)도 문구 표를 따른다.

### 3. 상단 바 (`AppShell.tsx`, `Account.tsx`)
- 왼쪽 "간호사 근무표 · 샘플 병동 · 한 달 단위"(`unitShort`).
- 저장 상태·계정은 그대로. 로그인 관련 대화상자는 샘플 저장 여부, 서버 우선 안내, 데이터 삭제만 남는다(step 1에서 로그인 요구 대화상자는 없앴다).

## 검증 절차

1. 위 AC 커맨드를 실행한다.
2. 수동 확인: `npm run dev` → `/app` 시작 화면(로그인 카드 없음) → 샘플 → 홈에 운영 중 10월 카드 + 지금 할 일(11월, 요청 3개, 생성 전) → [이어서 하기] → ③ 만들기 → 홈으로 돌아와 문장이 "근무표를 만들었어요…"로 바뀌는지 → 확정 → 홈에서 [12월 근무표 만들기]가 Primary인지. 빈 병동으로 시작했을 때 홈 안내도 확인한다. 확인 후 서버를 종료한다.
3. UI_GUIDE 체크: 홈의 Primary는 하나, 같은 근무표가 두 번 나오지 않음, 페이지 제목 하나.
4. 결과에 따라 `phases/3-ux/index.json`의 해당 step을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약"`
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요 → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단
