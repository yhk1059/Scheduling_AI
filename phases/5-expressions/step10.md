## 배경

결정 ★4·★5: 병동 조건을 시스템이 폼으로 강제하지 않는다. 처음 설정 ②는 **병동 소개**(말로 근무 형태와 필요 인원)로 바꾸고, 숫자 폼은 접힌 보조 수단이 된다. 필요 인원은 최소·최대 범위를 받는 **기본 규칙**이고, 근무조 합계로 "쉴 사람이 없어요"를 띄우던 오류는 없앤다(가능 여부는 솔버가 판정). 카드 자체의 새 모양(밑줄 값, 예시 띠)은 step 11이다.

## 작업

UI 컴포넌트는 TDD 대상이 아니다. build·lint·수동 저니로 검증한다.

### 1. 처음 설정 ② 병동 소개 (`SetupFlow.tsx`)
- 스테퍼 이름 "② 병동 소개". 맨 위 근무 형태 요약 한 줄 + [바꾸기](지금 그대로).
- 설명 한 줄 "근무 형태와 날마다 필요한 인원을 말로 적어 주세요" + 자연어 입력 바(병동 규칙 탭과 같은 컴포넌트, scope ward) + 예시 Text 버튼 2개("데이 평일 3명 이상, 주말 2명, 더블도 있어", "나이트는 매일 2~3명").
- 생긴 카드(설정 변경 카드 + 필요 인원 카드 `기본` 배지)를 입력 바 아래에 둔다. [적용]해야 반영된다.
- 그 아래 접힌 "숫자로 입력하기" Text 버튼(`aria-expanded`) → 펼치면 필요 인원 폼.
- [다음]은 항상 누를 수 있다. 누르면 `markIntroSeen()`. 필요 인원 규칙이 하나도 없으면 Primary 옆에 "필요 인원 없이 만들면 인원을 맞추지 않아요" 한 줄.
- ③의 "규칙 없이 만들면 필요 인원만 지켜요" → "규칙 없이 만들면 기본 규칙만 지켜요".

### 2. 필요 인원 폼 (`CoverageForm.tsx`)
- 칸마다 최소·최대 숫자 두 개 + "명"("3 ~ 4 명"). 최대를 비우면 "이상", 같으면 정확히. 값은 `coverageRange`로 읽고 `setCoverage`로 쓴다.
- 설명 한 줄 "하루에 그 근무조에 들어갈 간호사 수예요. 최대를 비우면 그 이상이면 돼요."
- **근무조 합계 "하루 n명 근무 · m명 쉼" 줄과 "쉴 사람이 없어요" 오류를 지운다.**
- 오류: 숫자가 아니면 "인원은 숫자로 적어 주세요.", 최소 > 최대면 "최소가 최대보다 커요."
- 폼 모양에 맞지 않는 필요 인원 규칙(토요일만 등)은 폼에 나오지 않는다(카드로만).

### 3. 병동 규칙 기본 카드 (`WardSettings.tsx`, `RulesStep.tsx`)
- 기본 규칙(`default: true`) 카드를 목록 맨 위에 `기본` 배지(UI_GUIDE "배지"의 중립 색)로. 버튼은 [삭제] 대신 [끄기]/[다시 켜기]. 홈 요약의 병동 규칙 수 규칙("필요 인원은 따로 센다")은 그대로.
- 병동 설정 [명단·필요 인원] 탭의 필요 인원 폼도 같은 새 폼을 쓴다.

### 4. 동작 확인 (수동 저니, 임시 Playwright 가능·커밋하지 않음)
1. 빈 병동 → 3명 명단 → ② 예시 "데이 평일 3명 이상, 주말 2명, 더블도 있어" 입력 → 설정 카드(DE) + 필요 인원 카드 → [모두 적용] → 폼 펼침에 값 반영.
2. 6명 명단에 D·E·N 각 3명(정확히)을 넣어도 폼에 오류가 없다 → 근무표 만들기 → 해 없음 패널이 이유를 보여 준다.
3. 필요 인원 없이 [다음] → 안내 한 줄 → ③ → [첫 근무표 만들기] 가능.
4. 병동 설정에서 필요 인원 기본 카드 [끄기] → 다시 켜기.
콘솔 오류·API 오류가 없어야 한다.

## 검증 절차

1. 위 AC 커맨드를 실행하고, 위 수동 저니를 `npm run dev`로 확인한다. 3000/8000 포트를 다른 작업 트리가 쓰고 있으면 남의 프로세스를 끄지 말고, 수동 저니는 건너뛰었다고 summary에 적는다. 실제 Anthropic API를 쓴다(`.env.local`).
2. 아키텍처 체크: UI_GUIDE의 색·컴포넌트 규칙(AI 슬롭 안티패턴 포함)을 지켰는가? 화면 문구가 UI_GUIDE "문구" 표와 같은가(hard/soft 대신 반드시/가능하면)?
3. 결과에 따라 `phases/5-expressions/index.json`의 해당 step을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약(바뀐 화면, 수동 저니 결과, 접근성 이름, 결정)"`
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - `blocked`는 쓰지 않는다. UI_GUIDE에 없는 세부는 기존 컴포넌트 모양을 따르고 summary에 `결정: …`으로 적는다.

## 금지사항

- 근무조 합계로 진행을 막거나 오류를 띄우지 마라. 이유: 결정 ★4, 복합 코드와 다른 규칙 때문에 합계로는 판정할 수 없다.
- ② [다음]을 비활성화하지 마라. 이유: 필요 인원은 필수 입력이 아니다(PRD J1).
- 카드 컴포넌트의 밑줄 값·예시 띠를 이 step에서 만들지 마라. 이유: step 11이다.
- 테스트를 통과시키려고 `data-testid` 같은 테스트 전용 속성을 넣지 마라. 접근성 역할·이름을 쓴다.
- 기존 테스트를 깨뜨리지 마라.
