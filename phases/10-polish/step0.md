# Step 0: holidays-lib

## 읽어야 할 파일

먼저 아래 파일들을 읽고 프로젝트의 아키텍처와 설계 의도를 파악하라:

- `/CLAUDE.md` — `lib/`의 순수 함수는 TDD
- `/docs/ARCHITECTURE.md` — "디렉토리 구조 › lib/"
- `/docs/ADR.md` — ADR-015(기간 날짜 계산은 UTC 자정 일수로), ADR-018(기간은 연속)
- `/lib/period.ts` — `PeriodRange`, `periodDays`, `dateOfDay`, `dayOfDate`, `isWeekendDay`. 날짜 문자열을 다루는 방식(타임존 무관)
- `/lib/period.test.ts` — 테스트 작성 방식

## 배경

phase `10-polish`는 매니저와 직원이 앱을 한 주기 더 써 본 뒤 나온 다듬기다. 지금 근무표를 만들면 공휴일이 비어 있고("공휴일 없음 · 바꾸기") 매니저가 ① 준비 요약을 펼쳐 달력에서 하나씩 눌러야 한다. 이 phase는 근무표를 만들 때 한국 공휴일을 자동으로 넣는다. 이 step은 **데이터와 순수 함수만** 만든다. store와 화면은 step 1이 바꾼다.

데이터는 외부 API를 쓰지 않고 `lib/`에 연도별 상수로 둔다(ARCHITECTURE "쓰지 않는 것": 외부 의존 추가 금지, 백엔드 무상태). 2026~2027년만 둔다. 상수에 없는 연도는 공휴일 없음으로 둔다(앱이 틀린 날을 넣는 것보다 비어 있는 편이 낫다).

## 작업

TDD: `lib/holidays.test.ts`를 먼저 쓰고, 통과하는 `lib/holidays.ts`를 만든다.

1. `lib/holidays.ts`(새 파일, `lib/period.ts`만 import):

   ```ts
   import type { PeriodRange } from "./period";

   /** 연도별 관공서 공휴일(대체공휴일·선거일 포함). "YYYY-MM-DD" 오름차순. 상수에 없는 연도는 빈 배열로 본다. */
   export const KR_HOLIDAYS: Record<number, { date: string; name: string }[]>;

   /** 기간 안의 공휴일을 날짜 인덱스(1..length, 오름차순)로. 상수에 없는 연도는 넣지 않는다. */
   export function holidayDays(period: PeriodRange): number[];

   /** 날짜의 공휴일 이름. 아니면 null. (① 달력의 title/aria-label용) */
   export function holidayName(date: string): string | null;
   ```

2. `KR_HOLIDAYS`는 아래 표를 그대로 쓴다(관공서의 공휴일에 관한 규정, 2023년 개정 대체공휴일 기준: 삼일절·광복절·개천절·한글날·어린이날·부처님오신날·성탄절은 토·일·다른 공휴일과 겹치면 다음 평일로 대체, 설·추석 연휴는 일요일·다른 공휴일과 겹칠 때만 대체, 신정·현충일은 대체 없음). 토·일에 걸린 날도 그대로 넣는다(그날이 공휴일인 것은 사실이고, `isWeekendDay`는 어차피 주말이다).

## 금지사항

- 공휴일 API·패키지를 쓰지 마라. 이유: 외부 의존을 늘리지 않는다(ARCHITECTURE). 상수로 충분하다.
- `backend/`에 공휴일을 두지 마라. 이유: 공휴일은 클라이언트 상태(`WorkPeriod.holidays`)이고 백엔드는 받은 인덱스만 쓴다.
- `lib/store.ts`·화면을 고치지 마라. 이유: step 1이 한다.
- 음력 계산 코드를 쓰지 마라. 이유: 상수 표로 충분하고 계산이 틀리면 찾기 어렵다.
- 기존 테스트를 깨뜨리지 마라.
