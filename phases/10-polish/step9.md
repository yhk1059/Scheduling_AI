## 배경

step 0~8이 화면을 바꾸는 동안 e2e는 돌리지 않았다. 이 step은 누적 summary를 바탕으로 e2e와 문서를 새 화면에 맞추고 전부 통과시킨다. 앱 코드는 e2e를 통과시키기 위한 최소 수정만 한다.

이 phase에서 바뀐 것(summary로 확인하라):
- 새 근무표에 한국 공휴일 자동(step 0·1) → UI로 만드는 근무표 중 12/25·1/1·설 등이 든 기간의 주말·공휴일 칸 수, 필요 인원, "공휴일 n일" 문구가 달라진다. 시드(`fixtures`)는 그대로.
- ② 요약표가 켜진 반드시 필요 인원 규칙 전부를 합친다(step 2) + 표 아래 한 줄.
- ③ 만들기 전 한 줄이 "제출 n/m명 · 반드시 n개 · …"로(step 3). "가능 시간과 매장 조건으로 근무표를 만들어요"는 없어졌다.
- 조사(step 4·5) → `"{code}로 고정"` 같은 접근 가능한 이름의 조사가 바뀔 수 있다. LLM 설명의 이름 뒤 조사.
- 직원 캘린더 직사각형 드래그 + [모든 날에 복사] + 안내 한 줄(step 6·7).
- 충돌 경고 인용 꼴, 제출 0명 안내([① 가능 시간으로]), 확정 화면 문장, 문구 훑기(step 8).

## 작업

1. `npm run test:e2e`를 돌려 실패를 모은다. 실패마다 원인을 셀렉터·문구·구조·결과 변화 중 어느 것인지 적는다.
2. `e2e/test-helpers.ts`와 spec을 새 화면에 맞춘다. 역할·접근 가능한 이름 우선. 시나리오가 검증하는 것(반드시 규칙 준수, 가능 시간 안 배정, 최소 변경, 확정 뒤 링크 잠금, 이월 표)은 바꾸지 않는다.
   - S7: 기존 같은 열 드래그는 그대로 통해야 한다. **열을 건너는 드래그 한 번**(예: 11/3 09:00 → 11/5 11:30, 3열 × 6칸 = 18칸)과 [모든 날에 복사] 한 번을 더하고, 그 뒤 칸 수를 센다. 이후 단계(S9의 "완전히 덮는 근무조만 배정")의 기대값이 바뀌면 추가 드래그를 **되돌리는** 드래그로 끝내 기존 34칸을 유지한다(시나리오의 뒷부분을 바꾸지 않기 위해).
   - S9-b: ③ 첫 화면 문장을 새 요약 한 줄로(제출 12/12명 등 시드 기준 값).
   - S8-a: 요약표 값이 말로 만든 규칙에 반응하는 것을 한 줄 더한다(기존 값은 폼 규칙만 있어 그대로).
   - S10: 근무표 없음 패널 순서 그대로(제출자가 있는 시나리오). **제출 0명 안내**는 새 시나리오 S19로 더한다: 다음 근무표를 시작해 아무도 제출하지 않고 ③ [근무표 만들기] → 안내 문장과 [① 가능 시간으로]만, 끄기 버튼 0개, `explain` 요청 없음(네트워크 요청 수 또는 `explaining` 표시 없음).
   - S12: 확정 화면 문장("직원은 같은 링크에서 근무표를 봐요").
   - S15: 다음 근무표(12/15~)에 공휴일이 자동으로 들어가면 "공휴일 n일"과 주말·공휴일 필요 인원 기대값을 맞춘다. 근무표 결과 검사(반드시 규칙 준수)는 공휴일을 반영한 `expectHardRulesHold`로 그대로.
   - 칸 고정 `aria-label`의 조사가 바뀌었으면 셀렉터를 정규식으로("{code}(으)로 고정").
   - 조사 변경으로 문장 비교가 깨진 곳은 새 문장으로.
3. 앱 코드는 접근성 규칙(UI_GUIDE "접근성")을 어겨 e2e가 못 찾는 경우에만 고친다. 그 밖의 앱 수정은 하지 않고 summary에 남긴다.
4. 문서를 새 화면대로 고친다. 시나리오 번호는 유지하고 S19를 더한다.
   - `docs/BROWSER_TEST_SCENARIOS.md`: S7·S8-a·S9-b·S12·S15 갱신, S19 추가, "테스트 데이터"에 "UI로 만든 근무표는 한국 공휴일이 자동으로 들어간다(시드는 고정값)".
   - `docs/UI_GUIDE.md`: ① 준비 요약(공휴일 자동, 달력 도움말), ② 요약표("켜진 반드시 필요 인원 규칙을 합친 값", 일부 날짜 규칙은 카드, 말로 만든 전일 규칙은 표와 카드 둘 다), ③ 버튼 표의 "만들기 전" 설명 한 줄 → 요약 한 줄 꼴, 해 없음 패널의 미제출 분기, 직원 캘린더 "드래그"(열을 건너 직사각형, [모든 날에 복사], 안내 줄), 확정 근무표 문장, "규칙·요청 카드"의 충돌 경고 인용 꼴, "문구" 표(바뀐 말이 있으면).
   - `docs/PRD.md`: J2 ① "공휴일은 자동으로 들어가고 매니저가 고칠 수 있다", ② 요약표 한 줄, ③ 만들기 전 요약, "직원 화면" 드래그 문장, J8 미제출 분기, "MVP 제외 사항"에 "폰에서의 가능 시간 입력(터치 드래그)"가 없으면 더한다.
   - `docs/ARCHITECTURE.md`: 디렉토리 구조에 `lib/holidays.ts`, "가명화" 패턴에 "복원할 때 이름 뒤 조사를 받침에 맞춘다".
   - `docs/ADR.md`: ADR-024 한 항목 — 공휴일은 연도별 상수(외부 API 없음, 2026~2027, 매니저 수정이 최종), ② 요약표는 켜진 반드시 필요 인원 규칙의 합(일부 날짜 규칙 제외), 조사는 결정적 후처리(클라이언트 `josa` + 서버 `restore`), 미제출 안내는 근무표 없음일 때만(PRD 원칙 유지). 형식은 기존 항목(결정·이유·트레이드오프)과 같게.
   - `README.md`: 기능 목록에 공휴일 자동·직사각형 드래그가 들어갈 자리가 있으면 한 줄씩.
5. `scripts/record-dining.ts`·`scripts/record-demo.ts`가 바뀐 문장·셀렉터를 쓰면 맞춘다. 영상(`public/demo.mp4`)은 다시 만들지 않는다(③ 첫 화면 문장과 확정 화면 문장이 바뀌어 "재녹화 필요"를 summary에 적는다).
6. `npm run test:e2e`가 전부 통과할 때까지 2~3을 반복한다.

## 검증 절차

1. 위 AC 커맨드를 실행한다. `test:e2e`는 `.env.local`의 `ANTHROPIC_API_KEY`·테스트 Supabase 키·`E2E_TEST_EMAIL`/`PASSWORD`가 필요하다. 키가 없으면 `blocked`로 두고 사유를 적는다. **e2e 실패는 `blocked`가 아니라 `error`**로 보고해 재시도되게 한다(실패한 spec 이름과 원인을 `error_message`에).
2. 아키텍처 체크: e2e가 검증하던 불변식이 그대로 검증되는가? 앱 수정이 접근성 수정뿐인가? 문서의 함수·파일 목록이 코드와 같은가?
3. 문서 체크: BROWSER_TEST_SCENARIOS의 S7·S9-b·S15·S19는 갱신한 spec 실행으로 갈음한다.
4. 결과에 따라 `phases/10-polish/index.json`의 해당 step을 업데이트한다:
   - 성공 → `"status": "completed"`, `"summary": "산출물 한 줄 요약(고친 spec·헬퍼, 앱 수정, 고친 문서, 남긴 문제, 영상 재녹화 필요)"`. 문서에 없는 세부 결정은 `결정: …`으로 함께 적는다.
   - 수정 3회 시도 후에도 실패 → `"status": "error"`, `"error_message": "구체적 에러 내용"`
   - 사용자 개입 필요(키 없음) → `"status": "blocked"`, `"blocked_reason": "구체적 사유"` 후 즉시 중단

## 금지사항

- e2e가 검증하는 조건을 약하게 만들지 마라(기대값 삭제, `force` 남용, 타임아웃만 늘리기). 이유: 테스트는 솔버·LLM 안전 장치의 증거다. 공휴일 때문에 결과가 달라진 검사는 공휴일을 반영한 기대값으로 바꾸고 원인을 summary에 적는다.
- 시나리오를 통과시키려고 화면 구조나 문구를 되돌리지 마라. 이유: 화면은 step 0~8의 결정이 기준이다. 셀렉터를 바꾼다.
- `e2e/fixtures/*.json`의 공휴일을 자동값으로 바꾸지 마라. 이유: 시드는 고정값이고 S3·S4의 기대값이 묶여 있다.
- `NEXT_PUBLIC_E2E_LOGIN`을 `.env.local`에 넣지 마라. 이유: 7-availability step 4 결정(playwright.config.ts의 서버 env로만 켠다).
- `eval/results.md`를 손으로 고치지 마라. 이유: `eval/run.py`가 쓴다.
- `public/demo.mp4`를 다시 녹화하지 마라. 이유: 시간이 길고 사용자가 따로 한다. 스크립트만 맞춘다.
- Supabase MCP 도구로 DB를 바꾸지 마라. 이유: 이 phase에 마이그레이션이 없다.
- 기존 테스트를 깨뜨리지 마라.
